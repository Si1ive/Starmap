# 命令执行规范（强制）

## 核心原则

**执行命令前必须说明：**
1. **命令做什么** - 这个命令的功能
2. **目的是什么** - 为什么要执行这个命令
3. **预期结果** - 执行后应该得到什么

**执行命令后必须输出：**
1. **实际结果** - 命令的实际输出
2. **分析结论** - 结果意味着什么
3. **下一步行动** - 基于结果要做什么

**禁止：**
- ❌ 不说明就执行命令
- ❌ 执行后不分析结果
- ❌ 只执行不解释
- ❌ 结果异常不告知

**必须：**
- ✅ 执行前说明目的
- ✅ 执行后分析结果
- ✅ 异常时明确告知
- ✅ 让用户了解进展

## 命令分类说明

### 文件操作命令

| 命令 | 功能 | 示例说明 |
|------|------|---------|
| `mkdir` | 创建目录 | "创建backend/app目录，用于存放后端应用代码" |
| `touch` | 创建文件 | "创建__init__.py文件，标记Python包" |
| `cp` | 复制文件 | "复制配置文件模板到项目目录" |
| `mv` | 移动文件 | "重命名文件为规范名称" |
| `rm` | 删除文件 | "删除临时文件，清理环境" |

### Git命令

| 命令 | 功能 | 示例说明 |
|------|------|---------|
| `git init` | 初始化仓库 | "初始化Git仓库，开始版本控制" |
| `git add` | 添加文件 | "将新创建的文件加入暂存区" |
| `git commit` | 提交更改 | "保存当前开发进度" |
| `git push` | 推送代码 | "将本地代码推送到远程仓库" |
| `git pull` | 拉取代码 | "获取远程最新代码" |

| `git merge` | 合并分支 | "将功能分支合并到开发分支" |
| `git log` | 查看历史 | "查看提交记录，确认版本" |

### 容器命令

| 命令 | 功能 | 示例说明 |

## 执行规范

### 简单命令（单行）

对于简单的单行命令，可以简化说明：

```markdown
**执行：** `ls -la`（查看当前目录文件列表）

**结果：** 正常，显示所有文件
```

### 复杂命令（多行/管道）

对于复杂命令，必须详细说明：

```markdown
**准备执行复杂命令：**

```bash
podman-compose -f docker-compose.podman.yml up -d
```

**说明：**
- `podman-compose -f docker-compose.podman.yml up`：启动当前项目定义的 Podman 服务
- `-d`：后台运行（detached模式）
- 启动基础设施服务，不启动后端和前端

**目的：** 先启动基础设施服务，验证数据库连接后再启动应用

**预期：** 三个容器状态为Up

**执行结果：**
```
[+] Running 4/4
 ⠿ Network starmap_default      Created
 ⠿ Container starmap-qdrant      Started
 ⠿ Container starmap-redis-1     Started
 ⠿ Container starmap-mysql-1     Started
```

**结论：** ✅ 所有服务启动成功
```

### 危险命令

对于可能产生影响的命令，必须警告：

```markdown
⚠️ **警告：即将执行危险命令**

**命令：**
```bash
rm -rf node_modules
```

**风险：** 删除所有依赖，需要重新安装

**目的：** 清理依赖，解决安装问题

**是否执行？** [需要确认]
```

## 违规处理

| 违规情况 | 处理方式 |
|---------|---------|
| 不说明就执行命令 | 用户要求补充说明 |
| 执行后不分析结果 | 用户要求补充分析 |
| 结果异常不告知 | 用户要求解释原因 |
| 命令执行不明确 | 用户要求澄清目的 |

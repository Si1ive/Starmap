# 开发日志规范（强制）

## 核心原则

**每个工程师在开发时，必须记录：**
1. **开发内容** - 做了什么
2. **遇到的问题** - 遇到什么困难
3. **修复方式** - 如何解决
4. **经验教训** - 学到什么

**禁止：**
- ❌ 开发完成后不记录
- ❌ 记录过于简单（如"完成开发"）
- ❌ 不记录遇到的问题
- ❌ 不记录解决方案

**必须：**
- ✅ 每次开发后记录
- ✅ 遇到问题立即记录
- ✅ 解决后记录方案
- ✅ 定期回顾总结

---

## 日志结构

### 个人开发日志

每个工程师维护一个个人日志文件：

```
docs/logs/
├── backend-log.md    # 后端工程师日志
├── frontend-log.md   # 前端工程师日志
├── data-log.md       # 数据工程师日志
└── pm-log.md         # PM日志
```

### 日志格式

```markdown
# 开发日志 - [角色]

## 2024-01-15

### 10:00 - 12:00

**开发内容：**
- 实现人物搜索API
- 添加Redis缓存

**遇到的问题：**
1. Neo4j查询超时（问题#1）
   - 现象：查询人物关系时响应时间 > 5s
   - 原因：未添加索引

**修复方式：**
1. 问题#1
   - 方案：添加Neo4j索引
   - 命令：`CREATE INDEX person_name FOR (p:Person) ON (p.name)`
   - 结果：查询时间降至 200ms

**经验教训：**
- 数据导入前应先创建索引
- 大数据量查询必须使用索引

**提交记录：**
- `feat(backend): 添加人物搜索API`
- `perf(db): 添加Neo4j索引优化查询`

---

### 14:00 - 16:00

**开发内容：**
- 实现对话API基础框架

**遇到的问题：**
1. OpenAI API调用失败（问题#2）
   - 现象：返回 429 Too Many Requests
   - 原因：请求频率过高

**修复方式：**
1. 问题#2
   - 方案：添加请求限流和重试机制
   - 代码：使用 `tenacity` 库实现重试
   - 结果：调用成功率提升至 99%

**经验教训：**
- 第三方API必须添加重试机制
- 注意API限流策略

**提交记录：**
- `feat(backend): 添加对话API框架`
- `fix(backend): 添加OpenAI重试机制`
```

## 问题记录规范

### 问题编号

每个问题分配唯一编号：

```markdown
**遇到的问题：**
1. Neo4j查询超时（BK-2024-0115-01）
   - 角色：Backend
   - 日期：2024-01-15
   - 序号：01
```

### 问题状态

| 状态 | 说明 |
|------|------|
| 🟡 待解决 | 问题已记录，尚未解决 |
| 🟢 已解决 | 问题已解决，记录方案 |
| 🔴 阻塞中 | 问题阻塞开发，需协助 |
| ⚪ 已关闭 | 问题确认解决，关闭 |

### 问题模板

```markdown
**问题编号：** BK-2024-0115-01

**问题描述：**
Neo4j查询人物关系时响应时间过长

**现象：**
- 查询周杰伦的关系网络，响应时间 > 5s
- 查询其他人物也类似

**环境：**
- Neo4j版本：5.11.0
- 数据量：100个节点，500条关系
- 查询语句：MATCH (p:Person)-[r]-(n) WHERE p.name = '周杰伦' RETURN p, r, n

**尝试过的方案：**
1. 增加内存分配 - 无效
2. 优化查询语句 - 部分有效

**最终方案：**
添加索引：CREATE INDEX person_name FOR (p:Person) ON (p.name)

**结果：**
查询时间从 5s 降至 200ms

**经验教训：**
数据导入前应先创建索引，避免大数据量查询性能问题

**相关提交：**
- `perf(db): 添加Neo4j索引优化查询`
```

## 日志维护规范

### 频率要求

| 时间 | 要求 |
|------|------|
| 每次开发后 | 记录开发内容 |
| 遇到问题时 | 立即记录问题 |
| 解决问题后 | 记录解决方案 |
| 每天下班前 | 完成每日总结 |
| 每周五 | 完成周总结 |

### 质量要求

- **详细程度：** 足够让他人理解问题和方案
- **可追溯性：** 包含提交记录、问题编号
- **可搜索性：** 使用关键词、标签

### 审查机制

- PM每周审查日志
- 团队每月回顾技术积累
- 优秀方案纳入知识库

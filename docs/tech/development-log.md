# 开发日志规范

## 核心原则

每次较完整的开发活动都应记录：

1. 做了什么
2. 遇到什么问题
3. 如何解决
4. 后续风险或待办

## 推荐结构

```markdown
## YYYY-MM-DD

### 开发内容
- 新增或修改的功能

### 问题记录
- 现象
- 原因
- 处理方式

### 验证结果
- 本地验证方式
- 是否通过

### 提交记录
- `feat(...)`
- `fix(...)`
```

## 示例

```markdown
## 2026-06-11

### 开发内容
- 调整 `RetrievalService` 的章节过滤逻辑
- 更新管理端检索调试页

### 问题记录
- 检索结果混入其他学科内容
- 原因是 `subject_id` 过滤未正确下推到检索层
- 已修复过滤条件构建逻辑

### 验证结果
- 通过管理端搜索接口验证
- 学科过滤结果正确

### 提交记录
- `fix(search): 修复学科过滤失效问题`
```

## 文档边界

- 日志示例应优先使用当前 408 平台场景

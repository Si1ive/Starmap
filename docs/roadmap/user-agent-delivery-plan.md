## 1. 交付策略

按可独立验收的纵向闭环开发，不按“先把所有后端表建完，再一次性写前端”的方式推进。

每个切片必须同时具备：

- 用户可见入口。
- 公共用户 API。
- 持久化状态。
- Agent 或学习域行为。
- 错误和恢复状态。
- 自动测试。
- 最小运行监控。

## 2. 阶段 0：产品与工程基线

### 范围

- 对齐文字原型中的产品主线。
- 接入设计 Skill，完成桌面和移动端高保真原型。
- 确定用户端视觉系统和组件策略。
- 清理现有用户端模板状态与过时页面结构。
- 建立用户端独立路由前缀与认证方案。

### 验收

- P01-P20 页面清单中的首发页面有完整高保真原型。
- J1、J2、J3、J4、J6 用户旅程可以在可点击原型中完整走通。
- FQ-01 选择题、FQ-02 简答题、FQ-03 长图文题在桌面和移动端均完成压力验证。
- 长题干、图片、公式、引用、运行状态、失败恢复和审批状态均有设计。
- 用户端不再依赖 `/admin/*` API。
- 产品、技术和数据模型决策记录一致。

## 3. 切片 1：提问到验证

### 用户价值

用户提出一个 408 问题，得到可追溯讲解，并能立即通过题目验证是否理解。

### 后端

- 学习用户和登录。
- Agent thread/run/event 基础模型。
- 公共知识检索门面。
- `explain` 工作流。
- 从审核题库组织 1 到 3 道验证题。
- SSE 运行事件。

### 前端

- Agent 工作区。
- 线程列表。
- 工具运行状态。
- 引用面板。
- “用题验证”动作。
- 内嵌练习面板。

### 验收

- 刷新或切页后，线程和运行状态可恢复。
- 回答至少能引用到知识点、题目或文档页。
- 验证题提交后形成作答记录。
- 无可靠来源时明确降级，不伪造引用。

## 4. 切片 2：做题到错题复习

### 用户价值

用户完成练习后，不只知道对错，还能看到错因并在合适时间再次验证。

### 后端

- 练习会话、题目快照、作答和用时。
- 客观题批改。
- 错题记录和错因分类。
- 复习调度。
- 掌握证据基础模型。

### 前端

- 专注练习工作区。
- 提交、跳过、标记不确定。
- 答案和解析。
- 错因确认。
- 错题队列与再次验证。

### 验收

- 题目内容更新后，历史练习仍保留当时快照。
- 重复提交具有幂等性。
- 错题不会因为查看解析自动标为已解决。
- 再次验证通过后，复习状态按规则变化。

## 5. 切片 3：诊断到今日计划

### 用户价值

系统根据目标、可用时间和真实学习证据，组织今天最值得完成的任务。

### 后端

- 用户档案和考试目标。
- 诊断会话。
- 周计划与今日任务。
- 任务重排规则。
- 基础掌握状态聚合。

### 前端

- 首次诊断。
- 今日工作台。
- 任务开始、跳过、完成和重排。
- 学习地图基础视图。

### 验收

- 推荐原因可以追溯到目标、错题或掌握证据。
- 修改可用时间后可预览计划影响。
- Agent 不能静默修改已确认的长期计划。
- 今日任务可从中断位置继续。

## 6. 切片 4：可恢复 Agent 工作流

### 用户价值

Agent 可以执行组题、复盘、调整计划等多步骤任务，用户能够观察、审批、中断和恢复。

### 后端

- 工具注册与权限等级。
- Agent step/checkpoint。
- 审批请求与决定。
- 结构化 artifact。
- 重试、取消和幂等。
- Agent 工作流评测集。

### 前端

- 运行步骤时间线。
- 待审批中心。
- 产物预览和编辑。
- 失败步骤重试。
- 全局任务状态中心。

### 验收

- 工具结果落库后，LLM 超时不会使结果消失。
- 用户离开页面后任务继续，回来可看到真实状态。
- 审批后从原检查点继续，不重复已成功步骤。
- 取消操作最终一致，界面不保留虚假运行状态。

## 7. 切片 5：用户资料

### 用户价值

用户可以把自己的讲义、笔记和题目加入当前学习上下文，同时清楚区分平台资料与个人资料。

### 后端

- 用户资料上传、解析、索引和删除。
- 用户级检索过滤。
- 引用来源隔离。
- 资料处理任务状态。

### 前端

- 资料列表。
- 上传和解析进度。
- 在线程中引用资料。
- 权限与模型外发提示。

### 验收

- 不同用户无法检索到彼此资料。
- 删除资料后原文件、索引和关联状态一致清理。
- 平台知识、个人资料和模型推断具有不同来源标记。

## 8. 阶段 6：按需增强客户端

### 8.1 PWA

仅在需要可安装入口、离线练习或更可靠通知时加入。

验收前提：

- 明确哪些数据允许离线。
- 解决题目答案缓存泄露和版本失效。
- 定义离线作答与在线同步冲突策略。

### 8.2 Tauri

仅在达到技术架构文档中的触发条件后加入。

首个桌面切片只做一条闭环：

`授权资料目录 -> 发现新文件 -> 用户确认 -> 上传/索引 -> 在线程中引用`

不在第一版桌面壳中加入通用终端或任意系统操作。

### 8.3 浏览器扩展

首个扩展切片：

`选中网页内容 -> 发送到指定 Agent 线程 -> 生成讲解或练习`

## 9. Agent 技术学习路线

这条路线让研发重点落在 Agent 核心，而不是客户端包装：

1. 结构化工具调用与结果校验。
2. 持久状态机和检查点。
3. SSE 事件流与断线恢复。
4. 工具幂等、重试和补偿。
5. 人在回路审批。
6. 多层记忆和可删除性。
7. 检索与引用评测。
8. 教学工作流离线评测。
9. 成本、延迟和成功率观测。
10. 最后再接本地能力和多客户端。

## 10. 建议开发顺序

1. 方向对齐和高保真原型。
2. 用户身份与公共 API 边界。
3. Agent thread/run/event 最小骨架。
4. “提问到验证”纵向闭环。
5. 练习、作答、错题和复习。
6. 今日计划与学习地图。
7. 审批、产物和复杂工作流。
8. 用户资料。
9. 根据真实需求选择 PWA、Tauri 或浏览器扩展。

## 11. 首发成功标准

首发版本不以页面数量验收，必须满足：

- 用户能完成“提问、讲解、验证题、错因、复习”的完整闭环。
- 每次回答和题目都能识别来源。
- 学习记录属于真实用户，而不是浏览器临时 session。
- Agent 任务切页后仍能恢复。
- 用户可以查看并控制长期记忆和计划修改。
- 用户端不依赖管理员权限。
- 至少有一套固定评测题验证检索、引用、组题和错因结果。

## 12. 暂不开发清单

- 桌面端安装和自动更新。
- 通用 Shell 工具。
- 多 Agent 自由协作框架。
- 3D 知识图谱。
- 社区和排行榜。
- 直播课程。
- 无证据的“AI 掌握度评分”。
- 在学习闭环完成前扩展大量模型提供商。

## 1. 文档目的

本文件是 408 学习 Agent 主体建设的产品和系统边界文件。它回答以下问题：

1. 用户如何从提问进入讲解、练习、批改、错因确认和复习，而不是停留在一次性聊天。
2. Agent 在什么范围内可以自主选择工具，什么动作必须经过用户审批。
3. 长任务如何被观察、取消、重试、恢复，以及服务异常后如何保留已经成功的结果。
4. 平台知识、用户上传资料、用户长期学习状态和模型推断如何隔离并被正确引用。
5. 学习进度如何由可追溯事实聚合，而不是由 Agent 随意写入一个百分数。
6. 管理员如何查看真实运行、标注问题、维护评测集，并在模型、Prompt 或工具变更前执行回归门禁。

本 PRD 不替代数据库迁移方案、详细 UI 规格或单个模块的工程设计。接口和字段在研发阶段可以细化，但不能违反本文定义的归属、状态、权限、幂等和可靠性约束。

## 2. 决策摘要

### 2.1 产品定位

产品是一个 **408 学习工作台**，不是普通聊天页、知识库和刷题工具的简单拼接。对话是用户发起任务的入口，学习任务、练习集、错因报告、复习任务和计划版本才是可持续的产品对象。

首发主闭环：

```text
用户提问
  -> 意图识别和上下文确认
  -> 受约束检索与引用
  -> 结构化讲解
  -> 用题验证
  -> 作答和批改
  -> 错因确认
  -> 生成可撤销的复习任务
  -> 后续间隔复习和掌握状态更新
```

### 2.2 Agent 形态

采用“确定性学习工作流 + 受约束 Agent 决策”的混合方案：

- 确定性代码负责学习主流程、状态转换、权限检查、题目快照、学习事实写入和复习调度。
- LLM 负责自然语言意图解析、查询改写、有限范围内的工具选择、解释生成、错因候选和主观题评分辅助。
- 每个工具都有版本、JSON Schema、超时、重试和幂等协议。
- Agent 只能通过领域命令写入学习数据，不能直接操作 ORM、SQL 或任意业务表。
- 长期计划、影响较大的个人数据修改和外部动作必须经过明确审批。
- 第一版不提供通用 Shell、任意本地命令、自由多 Agent 协作或无审批的长期写入。

### 2.3 端与服务边界

- 第一版采用响应式 Web，继续复用现有 React + Vite 用户端。
- Agent Runtime、工具执行、检查点、事件、记忆和评测都运行在服务端。
- 用户端使用 `/api/v1/app/*`，不直接调用 `/api/v1/admin/*`。
- 管理端继续使用 `/api/v1/admin/*`，并新增 Agent 运行与评测入口。
- 当前 `/api/v1/chat` 保留为兼容 RAG 问答接口，逐步迁移到 `agent` 和 `retrieval` 模块，不把同步 Chat 接口扩展成不可恢复的通用 Agent 接口。

### 2.4 评测结论

管理端必须提供评测中心。Agent 能力不能只看最终答案的语言质量，而应同时评估意图路由、检索和引用、工具调用、学习闭环、恢复能力、题目质量、批改质量、安全和成本。离线评测是变更发布门禁，线上评测是监控和抽样，人工复核用于沉淀新回归案例。

### 2.5 可靠性结论

Agent 的唯一真实状态在服务端。客户端断线、刷新、切页或关闭浏览器都不能丢失已提交的用户动作和已完成的工具结果。事件采用持久化序列号和 SSE 断点续传；工具结果先落库，再推进工作流；重试默认从最近检查点开始，不从头重复副作用。

## 3. 背景、问题和目标

### 3.1 当前问题

现有系统已经具备 408 学科、章节、知识点、题目、语料解析、Qdrant 检索、RAG 问答和管理员内容运营能力，但用户学习闭环仍不完整：

- 用户端 Agent 页面大量依赖 fixture 和本地状态，尚未连接真实 thread/run/event API。
- 当前 `/api/v1/chat` 以 `session_id` 为中心，同步返回回答，不能表达长任务和任务恢复。
- 没有持久化 `agent_run`、step、checkpoint、event 和 approval。
- `UserQuestionRecord` 不能独立表达真实用户、题目快照、作答事件、错因和长期掌握证据。
- 用户资料和平台语料尚未形成清晰的权限隔离和引用分层。
- 管理端已有内容审核和对话观察能力，但没有 Agent 评测数据集、运行对比、人工标注和发布门禁。

### 3.2 产品目标

首发版本需要让真实用户稳定完成以下任务：

1. 询问一个 408 知识点，得到基于可靠来源的结构化讲解。
2. 从讲解一键进入 1 至 3 道验证题，不泄露尚未作答的答案。
3. 完成作答后得到结果、错因候选和后续复习建议。
4. 切页、刷新或短暂断网后，仍能恢复线程、练习和 Agent 运行。
5. 上传自己的 PDF、图片或笔记，并在个人范围内检索和引用。
6. 在今日页看到由真实学习证据支持的任务，而不是无依据的推荐分数。
7. 管理员能够发现错误引用、题目污染、工具失败和模型退化，并将问题转成回归用例。

### 3.3 非目标

首发不做：

- 通用办公或浏览器自动化 Agent。
- 任意网站、桌面软件或本地终端操作。
- 用户之间共享私有资料和社交社区。
- 完整网盘、笔记软件或课程直播系统。
- 无人工审核的正式题库自动发布。
- 用一次聊天、一题答对或模型主观判断直接宣布用户“已经掌握”。
- 以隐藏思维链为产品展示或评测对象。
- 以泄露代码为能力依据。Claude Code 仅参考其公开产品文档和可验证的工程模式。

## 4. 用户与使用场景

### 4.1 用户角色

| 角色 | 主要目标 | 核心风险 |
|------|----------|----------|
| 备考用户 | 理解知识、完成练习、改善薄弱点 | 误导性解释、重复题、进度失真、资料泄露 |
| 内容审核员 | 修正知识点、题目、来源和标签 | 误发布、来源丢失、审核状态不一致 |
| Agent 运营/评测员 | 观察运行、维护评测集、比较版本 | 只看平均分、无法复现、成本失控 |
| 系统管理员 | 管理用户、权限、模型和系统健康 | 越权、配置误操作、敏感数据暴露 |

### 4.2 关键用户任务

- “我不会这个知识点，请讲到我能做题。”
- “给我几道适合当前水平的题，不要把答案提前告诉我。”
- “我做错了，告诉我错在概念、条件、计算还是方法。”
- “根据最近的错误，今天最应该复习什么？”
- “把这份自己的讲义和平台知识结合起来，但要分清来源。”
- “为什么 Agent 做了这个动作？我能否拒绝或撤销？”

### 4.3 必须覆盖的异常场景

1. 检索没有足够证据。
2. 题库候选不足或题目质量被审核阻断。
3. 工具成功但后续模型超时。
4. 运行中用户刷新、切页、重复点击或多设备打开。
5. 用户拒绝计划修改或资料处理审批。
6. 主观题包含图片、公式、小问或 A/B/C/D 寄存器名称。
7. 用户上传恶意文件、提示注入内容或包含敏感信息。
8. 模型输出结构化 JSON 不合规、引用不存在或答案泄露。

## 5. 产品原则与体验约束

### 5.1 行动优先于聊天

每次 Agent 运行至少应有一个明确的结果类型：`explanation`、`practice_set`、`grading_report`、`mistake_diagnosis`、`review_task`、`plan_draft` 或 `source_summary`。纯文字回答可以存在，但在能形成下一步动作时，应提供结构化按钮或产物。

### 5.2 证据先于断言

回答中的内容必须区分：

- 平台知识库事实。
- 平台原题或审核题事实。
- 用户资料事实。
- Agent 基于证据的推断。
- 未被资料支持的通用模型知识。

没有足够证据时，Agent 必须明确说“平台资料不足”，可以询问澄清或提供标记为推断的辅助说明，禁止伪造来源、页码、题号、答案或题库状态。

### 5.3 状态真实且可恢复

“正在处理”必须对应服务端真实运行。客户端不能因为 SSE 连接断开就把任务标成失败，也不能因为重新挂载组件就重复提交。

### 5.4 高风险写入可解释、可撤销

审批面板必须展示动作、原因、影响范围、写入对象、变更前后差异和撤销方式。审批前不产生长期写入；审批通过后必须记录决定人、时间、版本和幂等键。

### 5.5 不暴露隐藏思维链

用户看到的是安全的行动摘要、工具状态、来源、结果和下一步，不是模型逐 token 推理或内部提示词。管理员看到的是可审计的 action trace、工具输入输出摘要、错误码、版本和结果证据，不以“思维链越长越好”衡量 Agent。

## 6. 系统边界与总体架构

```text
React Web 用户端                         React 管理端
        |                                      |
        | /api/v1/app/*                        | /api/v1/admin/*
        v                                      v
                 FastAPI API Gateway
                         |
               Modular Application Layer
       identity | agent | workspace | learning | practice
       user_sources | retrieval | content | corpus | operations
                         |
       Agent Runtime: workflow, tools, checkpoint, event, approval
                         |
          MySQL      Redis      Qdrant      Object Storage
        业务事实源   队列/事件   检索索引      文件和图片
                         |
                   MinerU 解析服务
```

### 6.1 现有能力复用

- `catalog`：学科、章节和大纲树。
- `content`：知识点、题目和审核元数据。
- `corpus`：平台文件、文档、页面、块、图表和公式资产。
- `retrieval`：Qdrant 检索、MySQL 来源补全和关系扩展。
- `operations`：管理员身份、系统设置和审计能力。
- `identity`：真实用户注册、登录、邮箱验证、OAuth、opaque session、CSRF 和密码找回。
- `chat`：迁移为 Agent 的问答或解释工具；保留旧接口作为过渡。

### 6.2 新增模块边界

```text
backend/app/modules/
  agent/          # Agent run、step、event、checkpoint、approval、tool registry
  workspace/      # thread、message、artifact、任务中心读模型
  learning/       # goal、plan、task、mastery、review、learning events
  practice/       # session、question snapshot、attempt、grading、mistake
  user_sources/   # 用户文件、解析、索引、来源权限
  evals/          # dataset、case、run、result、annotation、gate
```

模块之间通过服务接口或领域命令通信。Agent 模块可以调用学习域服务，但不可以绕过服务直接读写其他模块的 ORM 模型。

## 7. 用户端 PRD

### 7.1 信息架构

一级导航固定为：

1. 今日：推荐任务、继续未完成运行、复习队列和本日进度。
2. Agent：线程、运行状态、引用和结构化产物。
3. 学习地图：408 学科、章节、考点和掌握证据。
4. 练习：专项、智能组卷、错题重练、模拟和历史会话。
5. 错题：错因聚类、待复习队列和再次验证。
6. 资料：用户资料、解析状态、来源和删除管理。

账户设置、隐私、数据导出、模型使用说明和通知设置放到账户菜单。

### 7.2 页面需求

#### U-01 今日工作台，P0

展示：考试倒计时、当前阶段、今日推荐任务、任务预计时长、推荐原因、待复习错题、运行中的 Agent 和最近完成产物。

行为：

- `开始` 创建或恢复对应任务，不重复创建运行。
- `跳过` 记录用户行为，并重新计算当日读模型。
- `调整今天` 只影响今日任务排序或草稿；影响长期周计划时进入审批。
- `继续` 回到最近一个可恢复的线程或练习会话。

验收：每条推荐都能展开到目标、错题、掌握证据或计划约束中的至少一项；无学习记录的新用户显示“需要诊断”而非虚构掌握度。

#### U-02 Agent 工作区，P0

组成：线程列表、消息时间线、运行步骤摘要、引用面板、结构化产物、输入框、任务状态中心入口。

支持模式：问懂知识点、分析题目、生成验证题、复盘错误、制定计划、处理用户资料。自然语言可以自动路由，但必须允许用户在发送前选择模式，或在歧义时先澄清。

消息必须绑定 `thread_id` 和 `run_id`。一个用户消息可以触发一个主运行；重试是原运行的子操作或关联运行，不得在界面中伪装为新的无关联对话。

#### U-03 运行详情与任务中心，P0

展示运行状态：排队、规划、执行、等待用户、等待审批、完成、失败、取消或过期。

展示安全摘要：正在检索的范围、已找到几项候选、已生成几道题、等待什么输入、失败步骤和下一步选择。禁止显示隐藏 Prompt 和原始思维链。

操作：取消运行、重试失败步骤、从检查点继续、打开产物、回答澄清问题、处理审批。

#### U-04 引用与来源，P0

每条引用显示来源层级、标题、页码或题号、关联知识点、来源状态和可展开原文。来源层级至少包括：平台知识、平台原题、平台练习题、我的资料、模型推断。

引用打开失败时显示来源暂不可用，不回退成无来源的确定性表述。引用支持 `source_id`、`source_version_id`、`document_id`、`page_no`、`block_id` 或题目快照标识。

#### U-05 练习工作区，P0

支持选择题、判断题、填空题和主观题基础形态。主观题支持分小问草稿、图片展示、公式文本和自动保存；第一版不承诺完全可靠的数学公式编辑器，可先使用文本/Markdown 输入。

练习题必须在创建会话时保存快照，包括题干、选项、题型、答案版本、解析版本、来源标签、关联考点和资源引用。题库后续变更不得修改历史答题上下文。

未提交练习不展示正确答案。提示分层为方向提示、关键概念提示、解法提示，使用情况写入作答证据。

#### U-06 批改、错因与复习，P0

提交后先返回批改状态和客观结果；深度批改可以异步运行。用户能确认或拒绝错因候选，也能选择“无法判断”。

系统默认错因枚举：概念混淆、条件遗漏、计算错误、解题策略不熟、审题错误、知识未覆盖、表达不完整、时间管理。错因是可修正标签，不是人格判断。

错题只有经过后续验证和复习规则满足后，才能从待复习队列移出。查看答案、收藏或标记“已理解”不能直接改变掌握状态。

#### U-07 学习地图，P1

按学科、章节、知识点显示状态和证据：近期正确率、答题次数、提示使用、最近复习时间、待处理错题和平台考频。支持从节点进入讲解、专项练习和错题。

#### U-08 资料，P1

支持主动上传 PDF、图片、Markdown/纯文本，显示上传、解析、切块、索引和失败状态。用户能删除资料、查看处理范围、知道资料是否会被发送给模型，并能在会话内选择是否使用。

平台资料和个人资料始终分开显示；个人资料默认仅当前用户可访问，不参与平台知识库、不参与其他用户检索。

#### U-09 账户、隐私和数据控制，P0

提供会话管理、已登录设备、导出个人学习数据、删除用户资料、删除线程和申请删除账号。隐私说明必须解释：上传文件存储位置、解析链路、模型调用范围、保留时间和删除延迟。

### 7.3 用户端状态和交互门禁

所有 P0 页面至少设计并实现以下状态：空状态、加载、局部加载、运行中、等待用户、等待审批、完成、部分完成、失败、取消、权限不足、资源删除和网络断开恢复。

移动端要求：

- 运行时间线、引用、审批和题目内容不得互相覆盖。
- 长题干、公式、图片和答案区必须自然换行或纵向滚动。
- 练习输入控件在键盘弹出时仍能提交和保存。
- 桌面三栏在窄屏切换为主内容加抽屉，不把三栏强行缩小。

## 8. Agent 工作流和运行时

### 8.1 工作流优先级

首发工作流：

| 工作流 | 触发 | 是否写学习事实 | 级别 |
|--------|------|----------------|------|
| `explain` | 用户问知识点或题目 | 否，产生解释产物 | P0 |
| `validate` | 用户点击用题验证 | 创建练习草稿，会话提交后写作答事实 | P0 |
| `grade` | 用户提交答案 | 写批改事实和错因候选 | P0 |
| `review` | 到期复习或用户主动复习 | 写复习完成事实 | P0 |
| `mistake_diagnosis` | 作答错误或用户要求复盘 | 生成候选，用户确认后写确认事实 | P0 |
| `plan` | 首次诊断或计划调整 | 草稿自动，长期计划需审批 | P1 |
| `source_ingest` | 用户上传资料 | 写用户资料处理状态和索引 | P1 |
| `report` | 用户查看阶段报告 | 只读聚合 | P1 |

### 8.2 标准解释工作流

```text
接收消息
  -> 识别意图和已有上下文
  -> 检查是否需要澄清
  -> 查询改写
  -> 按条件检索知识点/题目/关系/用户资料
  -> 证据质量门禁
  -> 生成结构化解释
  -> 引用支持校验
  -> 保存消息和 explanation artifact
  -> 提供验证、追问和收藏动作
```

程序化质量门禁至少检查：引用 ID 是否真实、引用是否属于当前可见范围、核心断言是否有证据、题型和来源是否一致、回答结构是否符合 Schema。门禁失败时降级为“证据不足”或触发重试，不能静默输出。

### 8.3 验证题工作流

```text
锁定知识点和用户状态
  -> 读取题目候选
  -> 过滤审核不通过、重复、质量阻断和答案泄露候选
  -> 结构化检查题型/难度/来源
  -> 创建题目快照和 practice_session 草稿
  -> 返回练习产物
```

默认优先使用审核通过的原题或平台题。题目不足时可以生成 AI 练习题，但必须标注 `ai_generated`，不写入正式原题库；生成题必须通过答案一致性、题型一致性、知识点覆盖和重复性检查。

### 8.4 批改工作流

- 客观题：服务端根据快照答案确定性批改，LLM 不拥有最终答案判定权。
- 填空题：优先规则化归一化，歧义答案进入人工或模型辅助复核。
- 主观题：LLM 只输出评分点、证据片段、缺失点和置信度；最终展示“AI 辅助反馈”，不伪装成官方阅卷。
- 批改结果版本化，模型、Prompt、评分 Rubric 和题目答案版本必须可追溯。

### 8.5 Agent 动态决策的边界

LLM 可以在白名单内选择检索、读取用户状态、组织题目、生成解释和生成错因候选。以下决策由代码固定：

- 当前用户是否有权限访问资源。
- 题目是否可以被使用。
- 客观题正确答案。
- 学习事实和掌握状态如何落库。
- 是否需要审批。
- 幂等、重试、超时、取消和状态转换。
- 任何外部发送、删除和高风险本地动作。

## 9. 工具系统

### 9.1 工具协议

每个工具注册信息包含：`tool_key`、`version`、`description`、输入 Schema、输出 Schema、权限等级、可见资源范围、超时、最大重试次数、幂等策略、审计级别和人工回滚策略。

工具执行统一返回：

```json
{
  "ok": true,
  "tool_key": "retrieve_knowledge",
  "tool_version": "v1",
  "request_id": "...",
  "data": {},
  "warnings": [],
  "evidence": [],
  "usage": {"latency_ms": 0}
}
```

失败返回稳定 `error_code`、用户可理解的 `safe_message`、是否可重试、是否已产生副作用和建议动作。原始供应商错误只写入受控日志。

### 9.2 首发工具目录

| 工具 | 类型 | 默认权限 | 说明 |
|------|------|----------|------|
| `get_learning_context` | 只读 | 自动 | 读取当前用户目标、掌握证据、任务和相关错题 |
| `retrieve_knowledge` | 只读 | 自动 | 查询平台知识点、文档块和关系 |
| `retrieve_questions` | 只读 | 自动 | 按章节、题型、年份、难度和质量状态筛选题目 |
| `retrieve_user_sources` | 只读 | 自动但需用户选中资料 | 只读取当前用户授权的资料 |
| `create_explanation_artifact` | 临时产物 | 自动 | 保存结构化讲解和引用 |
| `create_practice_draft` | 临时写入 | 自动 | 生成未提交练习草稿和题目快照 |
| `grade_attempt` | 学习命令 | 自动 | 调用确定性客观批改或受控主观评分 |
| `propose_mistake_reason` | 临时产物 | 自动 | 生成错因候选和证据，不直接确认 |
| `confirm_mistake_reason` | 学习命令 | 用户确认 | 写入用户确认的错因 |
| `schedule_review` | 学习命令 | 自动或可撤销 | 根据已确认学习事实创建复习任务 |
| `propose_plan_change` | 临时产物 | 自动 | 生成计划变更差异，不写长期计划 |
| `apply_plan_change` | 长期写入 | 明确审批 | 通过版本检查后修改计划 |
| `ingest_user_source` | 用户数据写入 | 用户发起 | 上传、解析、索引当前用户资料 |
| `delete_user_source` | 删除 | 明确确认 | 删除文件、派生文本、索引和访问授权 |

第一版不注册 `shell`、`browser_automation`、`send_email`、`external_upload`、`read_arbitrary_local_path` 等通用或高风险工具。

### 9.3 工具权限分级

| 级别 | 示例 | 策略 |
|------|------|------|
| R0 只读 | 检索平台内容、读取当前状态 | 自动，强制用户范围过滤 |
| R1 临时产物 | 解释卡片、练习草稿、报告草稿 | 自动，用户可删除或重新生成 |
| R2 可撤销学习写入 | 保存笔记、确认错因、创建复习任务 | 用户动作触发或自动但可撤销，保留审计 |
| R3 长期学习写入 | 修改周计划、归档错题、批量调整目标 | 必须审批，显示差异和影响 |
| R4 外部/本地高风险 | 外发资料、执行命令、删除账号 | 首发禁止，未来逐项设计和授权 |

权限检查不能只依赖 Prompt。服务端在工具调用前再次检查：当前用户、资源归属、线程归属、当前审批状态、工具版本和业务前置条件。

### 9.4 幂等、重试和副作用

- 每个客户端写请求支持 `Idempotency-Key`。
- Agent step 使用 `run_id + step_key + input_hash` 生成服务端幂等键。
- 只读工具可以有限次指数退避重试。
- 具有副作用的工具必须先查询幂等记录，成功后保存结果，再发布完成事件。
- 不确定超时不能直接重试副作用工具；先查询执行记录或使用补偿动作。
- 用户重复点击提交、审批和取消时返回已有操作结果，不创建重复数据。

## 10. Agent Run、事件和恢复协议

### 10.1 运行状态机

```text
queued
  -> planning
  -> running
  -> waiting_for_user
  -> running
  -> waiting_for_approval
  -> running
  -> completed

planning/running -> failed
planning/running -> cancelled
waiting_for_user -> expired
waiting_for_approval -> expired
```

状态转换必须由服务端原子校验。终态不可回到运行态；重试创建新的 attempt 或从检查点创建关联运行，不修改已经完成步骤的历史状态。

### 10.2 Step 最小字段

- `step_id`、`run_id`、`step_key`、`sequence`。
- `step_type`：model、tool、gate、approval、artifact、domain_command。
- `status`、`input_hash`、`idempotency_key`。
- `started_at`、`completed_at`、`retry_count`、`timeout_at`。
- `error_code`、`safe_summary`、`output_artifact_id`。
- `model_config_id`、`prompt_version_id`、`tool_version`。

### 10.3 Event 最小字段

- `event_id`、`run_id`、`sequence`、`event_type`、`payload`、`created_at`。
- `payload` 只包含用户所需或管理员审计所需的安全摘要，不包含密钥、完整 Prompt、隐藏思维链或不必要的个人资料原文。
- `sequence` 在单个 run 内单调递增并建立唯一约束。
- SSE 支持 `Last-Event-ID`。服务端从事件表补发缺失事件；事件较旧时返回快照加新的事件游标。

首发事件：`run.started`、`step.started`、`step.progress`、`tool.started`、`tool.completed`、`artifact.created`、`approval.required`、`run.waiting`、`run.completed`、`run.failed`、`run.cancelled`、`run.expired`。

### 10.4 Checkpoint 和恢复

检查点记录可恢复的工作流节点、已完成 step、工具结果引用、输入版本、审批状态和恢复 token。恢复流程：

1. 读取最新有效检查点。
2. 校验线程、用户、工作流版本和依赖资源仍可用。
3. 跳过已成功且幂等确认的 step。
4. 从第一个未完成或可重试 step 继续。
5. 对过期资料、被删除题目或版本冲突返回需要用户处理的状态。

### 10.5 上下文预算与压缩协议

长线程不能把完整历史、检索原文和工具结果无限附加给模型。Agent Runtime 在服务端维护上下文预算，并以“可恢复引用 + 结构化摘要”替代不受控截断。

触发压缩的条件：

- 预计下一次模型调用会超过该模型可用上下文预算的 60%。
- 一个工作流完成检索、组题、批改等阶段性 step 后。
- 运行进入 `waiting_for_user` 或 `waiting_for_approval` 前。
- 单线程累计消息或工具结果达到配置阈值，即使尚未触及 token 上限。

每次压缩必须新建版本化 `thread_summary` 或 checkpoint 摘要，并保留原始消息和工具结果的可访问引用。摘要至少包含：

1. 当前用户目标、问题、工作流和未完成动作。
2. 已确认的学习事实、审批状态和不可重复的副作用结果。
3. 已采用的关键结论及其来源引用，不将模型推断写成来源事实。
4. 已排除的候选、失败原因、用户偏好和下一步应询问的澄清项。

禁止在压缩中丢失或改写：用户身份和授权范围、题目/答案快照、提交的作答、审批决定、幂等键、工具结果引用、引用来源、计划版本和用户明确的纠正。模型生成的摘要不是业务事实源；恢复时，领域事实仍从 MySQL 和 artifact/step 引用重新读取。

上下文组装顺序固定为：系统和安全规则、当前工作流状态、当前用户授权范围、不可变领域事实、最近用户消息、必要摘要、最少量检索证据。超过预算时先缩减低相关检索片段，再按版本化摘要压缩旧对话，不能截断当前用户指令、审批差异或未提交答案。

评测集必须覆盖“多轮长对话压缩后继续练习”“压缩后恢复审批”“压缩后不重复创建练习”三个场景，验证结论、引用、权限和副作用保持一致。

## 11. 学习域与进度更新

### 11.1 事实事件优先

Agent 不直接写 `mastery_percent`。系统先记录不可变或追加式的学习事实，再由聚合器更新读模型。

首发事实事件：

- `question_started`
- `answer_saved`
- `hint_viewed`
- `question_submitted`
- `objective_graded`
- `subjective_feedback_generated`
- `mistake_reason_confirmed`
- `review_scheduled`
- `review_started`
- `review_completed`
- `task_completed`
- `user_mastery_override`

每个事件必须带 `user_id`、事件时间、来源对象、题目快照或知识点、客户端、幂等键和 schema 版本。

### 11.2 掌握状态

首发状态：

```text
not_started -> learning -> needs_reinforcement
needs_reinforcement -> mastery_candidate
mastery_candidate -> mastered
任意状态 -> insufficient_evidence
```

建议同时保留 `state` 和证据指标，而不是只保存一个百分数：

- 独立作答次数。
- 最近 N 次正确率和连续正确次数。
- 是否使用提示及提示层级。
- 主观题评分点覆盖率。
- 间隔复习是否按期完成。
- 最近一次作答和复习时间。
- 证据质量和置信度。

一次答对可以改善状态，但不能单独从未学习跳到已掌握。用户明确标注“我已掌握”可作为偏好或覆盖事件，但必须与系统证据分开显示。

### 11.3 进度更新触发规则

| 动作 | 自动写入 | 是否需要用户确认 |
|------|----------|------------------|
| 开始查看讲解 | `learning_started` 或活动事实 | 否 |
| 完成客观题提交 | 作答和确定性批改事实 | 否 |
| 生成错因候选 | 草稿，不写确认错因 | 否 |
| 用户确认错因 | 错因确认事实 | 是用户动作 |
| 创建一次复习任务 | 复习调度事实 | 通常否，用户可撤销 |
| 修改周计划 | 计划草稿 | 是，必须审批 |
| 归档错题 | 归档草稿 | 是，必须审批或显式操作 |

## 12. 练习、批改、错题和复习

### 12.1 题目来源和质量等级

题目必须具备来源标签：

- `platform_original`：平台审核的原题或官方来源题。
- `platform_adapted`：平台基于原题改编并审核的题。
- `ai_generated`：模型生成、尚未成为正式题库事实的练习。
- `user_source`：用户资料中的题目。

FQ-01 至 FQ-07 继续作为首发验收和回归用例，特别验证：选项恢复、主观题识别、公式图片、低质量题阻断和生成题来源标记。

### 12.2 题目选择门禁

组题前必须过滤：审核未通过、结构不完整、答案缺失、解析冲突、来源不可追溯、重复度过高和已被质量规则阻断的题目。候选不足时减少题量或明确告知用户，不为凑数量降低质量门槛。

### 12.3 作答和快照

`practice_session_questions` 保存题目快照及版本，不依赖题库实时读取。答案草稿采用版本号或更新时间检查，避免多设备覆盖；冲突时提示用户选择，不静默丢失较新答案。

### 12.4 错因和复习

Agent 输出错因候选时必须引用作答证据，例如用户遗漏的条件、错误计算步骤或未覆盖评分点。用户可确认、修改、拒绝或标为无法判断。

复习调度首发采用规则化策略：根据错误严重程度、历史间隔、提示使用和再次验证结果计算下次复习时间。后续可以引入 FSRS 等成熟调度实现，但调度器必须版本化、可回放，不能由 LLM 随意决定日期。

## 13. 用户资料、图片和多模态入库

### 13.1 资料生命周期

```text
created -> uploading -> uploaded -> parsing -> indexed -> ready
                                      |          |
                                      v          v
                                   failed     deleting -> deleted
```

资料对象至少保存：用户归属、原始文件对象、SHA-256、MIME、大小、版本、解析状态、索引状态、可见范围、保留策略和删除时间。

### 13.2 处理规则

- 用户主动选择文件后上传，首发不扫描任意本地目录。
- 文件病毒扫描、MIME 校验、大小和页数限制在进入解析队列前执行。
- 解析产物沿用平台文档的页、块、图片、表格和公式分层，但增加 `owner_user_id` 和来源范围。
- 用户资料单独 collection 或强制 payload 过滤，不能与平台公共内容混淆。
- 用户资料引用显示“我的资料”，不得显示成平台权威内容。
- 用户删除资料后，原文件、派生文本、向量和缓存均进入删除流程；删除完成前不再参与新检索。
- 用户可以关闭某份资料在 Agent 中的使用，关闭只影响检索授权，不等于删除文件。

### 13.3 Prompt Injection 防护

用户资料和检索文本均是不可信内容。解析文本中出现“忽略系统指令”“调用某工具”“发送文件”等内容时，只能作为学习材料展示，不得改变 Agent 权限或工作流。工具描述、系统规则和用户资料在上下文中分层；工具执行前仍由服务端做权限和 Schema 校验。

### 14.1 现有入口保留

### 14.2 新增 Agent 运营入口

| 路由 | 作用 | 优先级 |
|------|------|--------|

| `/admin/agent-runs/:id` | 查看安全 action trace、step、tool、事件、引用、错误和成本 | P0 |
| `/admin/evals` | 评测总览、发布门禁和近期回归 | P0 |
| `/admin/evals/datasets` | 数据集版本、案例和标签管理 | P0 |
| `/admin/evals/runs` | 发起、排队、取消和比较评测运行 | P0 |

### 14.3 Agent Run 详情

管理员可以查看：

- 用户、线程、运行模式、状态和耗时。
- 模型配置、Prompt 版本、工具版本和数据集版本。
- step 时间线、工具调用输入输出摘要、重试、超时、错误码和检查点。
- 引用实体、页码、召回分数、引用支持检查结果。

- token、模型成本、队列等待和下游服务耗时。

管理员默认不能查看不必要的完整用户原文。敏感内容按权限脱敏；访问完整内容必须有审计理由。

### 14.4 评测入口为什么必须在管理端

Agent 的质量会随模型、Prompt、检索索引、题库、工具实现和策略变更而变化。没有后台评测入口，就无法复现线上问题、比较版本或阻止质量退化。评测中心不是面向用户显示一个“Agent 总分”，而是内部质量控制设施。

管理端必须支持：固定状态运行、模拟工具返回、模型和 Prompt 版本锁定、批量运行、逐案例结果、人工标注、结果对比、回归集沉淀和发布门禁。

### 14.5 内容质量联动

评测发现错误引用、题型误判、答案泄露或题目质量问题时，管理员可以从运行详情跳转到对应知识点、题目或语料审核页，创建质量问题并将案例加入评测集。评测案例和内容审核状态分开保存，不能用“评测通过”替代“题目审核通过”。

## 15. Agent 评测体系

### 15.1 评测层次

#### 离线回归评测

使用固定输入、固定用户状态、固定候选工具和固定工具返回，比较模型、Prompt、检索器、工作流和规则版本。适合发布前门禁。

#### 线上运行监控

对真实运行采集成功率、状态停留、引用质量、工具失败、恢复率、延迟、token、成本和用户反馈。线上数据不直接作为无审查的训练数据。

#### 人工复核

对抽样运行按 rubric 标注：事实正确、引用支持、教学清晰、动作合理、来源标签、题目质量、错因证据和安全性。发现的问题一键沉淀为固定案例。

### 15.2 能力指标

| 层级 | 指标 | 说明 |
|------|------|------|
| 意图 | route accuracy、clarification precision | 是否进入正确工作流，歧义是否先澄清 |
| 检索 | Recall@K、MRR、nDCG、低质题过滤率 | 是否找对证据和题目 |
| 引用 | citation support rate、错误引用率、页码准确率 | 核心断言是否可由引用支撑 |
| 诚实性 | evidence-insufficient accuracy | 证据不足时是否正确降级 |
| 工具 | tool selection、参数 Schema、顺序和权限准确率 | 是否调用正确工具、参数和顺序 |
| 工作流 | 完成率、幂等率、恢复率、取消成功率、审批正确率 | 是否可靠完成任务 |
| 题目 | 类型识别、难度匹配、重复率、答案一致性、来源标记准确率 | 是否能安全组题 |
| 批改 | 客观准确率、评分点覆盖率、证据对应率 | 是否能解释用户为什么错 |
| 学习 | 复习完成率、后续验证改善、错因确认一致性 | 是否形成有效学习闭环 |
| 运行 | p50/p95 延迟、失败率、队列等待、token、单次成本 | 是否可运营 |
| 安全 | 越权率、敏感信息泄露率、提示注入成功率、违规输出率 | 是否满足公开服务安全要求 |

不得将隐藏思维链长度、模型“像不像人”或单一总体奖励分作为核心指标。

### 15.3 固定评测集

首批固定案例至少包含：

- E01 循环队列 front 计算和 FQ-01。
- E02 含 A/B/C/D 寄存器名称的 FQ-02 主观题。
- E03 FQ-05/FQ-06 低质量或不完整题阻断。
- E04 FQ-03 长题干、公式和两张图片。
- E05 平台证据不足时诚实降级。
- E06 计划调整审批前后写入边界。
- E07 工具成功、模型超时和局部重试。
- E08 用户表达焦虑时回到具体学习证据，不做人格化结论。

每个案例包含：输入、固定用户状态、可用工具、工具模拟返回、允许的调用顺序、必须事实、禁止事实、引用事实集合、结构化 Schema、评分 rubric、模型/Prompt/工具/数据版本。

### 15.4 建议发布门禁

阈值需要在第一批人工标注完成后校准，以下是首发前的硬门禁方向：

- 核心引用不存在或引用越权：0 容忍。
- 客观题最终判定错误：核心集 0 容忍。
- 审批前发生长期写入：0 容忍。
- 题型和来源标签错误：核心集 0 容忍。
- 工具输入 Schema 错误、重复副作用：0 容忍。
- 核心集引用支持率、证据不足降级率、工作流完成率和恢复率不得低于当前生产基线。
- p95 延迟、失败率和单次成本不得超过发布前设定的预算上限。

不能以平均分掩盖单个高风险案例。任一安全、越权、答案泄露、虚假引用或数据隔离失败都可以阻断发布。

### 17.4 SSE 约束

`GET /agent/runs/{run_id}/events`：

- 返回 `text/event-stream`。
- 首次连接先发送当前快照，再发送游标之后的事件。
- 支持 `Last-Event-ID`，重复事件由客户端按 `event_id` 去重。
- 心跳不改变业务序列号。
- 运行结束后连接可以关闭，客户端通过 run 查询确认终态。
- SSE 不可用时客户端退化为轮询，不改变服务端状态。

### 17.5 错误协议

统一返回 `code`、`message`、`request_id`、`retryable`、`details`。典型错误：

- `AUTH_REQUIRED`、`FORBIDDEN_RESOURCE`。
- `RUN_NOT_FOUND`、`INVALID_STATE_TRANSITION`、`RUN_ALREADY_TERMINAL`。
- `IDEMPOTENCY_CONFLICT`、`VERSION_CONFLICT`。
- `SOURCE_NOT_READY`、`QUESTION_UNAVAILABLE`、`EVIDENCE_INSUFFICIENT`。
- `RATE_LIMITED`、`MODEL_TIMEOUT`、`TOOL_TIMEOUT`、`SERVICE_UNAVAILABLE`。

## 19. 安全、隐私和滥用防护

### 19.1 访问控制

- 用户端和管理端认证、会话和 CSRF 沿用身份模块既有方案。
- 资源级授权优先于路由级授权；任何 IDOR 测试失败都阻断发布。
- 管理员按角色限制内容编辑、用户支持、运行查看、评测运行和配置发布。
- 管理员查看用户原文、运行输入和资料内容时记录审计日志。

### 19.2 文件和资料安全

- 限制 MIME、扩展名、大小、页数、图片像素和压缩炸弹风险。
- 上传后先隔离扫描，再解析和索引。
- 对象存储使用不可猜测 key 和短时签名 URL。
- 解析服务使用最小权限、资源限制和任务超时。
- 删除是异步但可追踪的；删除请求后资源立即从新检索中排除。

### 19.3 LLM 和工具安全

- API key、系统 Prompt、内部 URL、数据库错误、其他用户内容不得进入用户输出。
- 检索内容按不可信文本处理，不能通过资料文本改变工具权限。
- 工具输入和输出均做 Schema 验证、长度限制和敏感字段过滤。
- 限制单用户并发 run、每日 token、文件处理量和工具调用次数。
- 模型输出禁止直接生成可执行命令；第一版无命令工具。
- 对未成年人和敏感内容制定单独策略；学习产品不输出人格、医疗或心理诊断。

### 19.4 数据生命周期

定义线程、事件、模型日志、文件原件、派生索引和评测副本的保留周期。用户删除操作必须覆盖主记录、对象存储、向量、缓存、异步队列和备份中的可删除副本，并返回可查询的删除任务状态。

## 20. 可靠性、故障处理和可观测性

### 20.1 故障分类

| 故障 | 用户表现 | 系统动作 |
|------|----------|----------|
| SSE 断开 | 时间线暂停 | 允许重连并补发事件，运行继续 |
| LLM 超时 | 当前步骤失败或重试中 | 保留已落库工具结果，支持局部重试 |
| 检索不可用 | 无法可靠回答 | 诚实降级，不使用未经验证缓存冒充引用 |
| 题库不足 | 练习题量减少 | 返回实际数量和原因，不使用阻断题 |
| Worker 崩溃 | 运行暂时停留 | 租约超时后恢复或标记可重试 |
| 重复请求 | 用户重复点击 | 幂等返回原资源或明确冲突 |
| 审批过期 | 计划未改变 | 展示过期原因，要求重新生成差异 |
| 版本冲突 | 计划/答案被其他设备更新 | 返回冲突并让用户选择 |

### 20.2 可观测性

所有运行关联 `request_id`、`trace_id`、`user_id`、`thread_id`、`run_id` 和 `step_id`。指标至少包括：

- API 请求率、错误率、p50/p95/p99 延迟。
- 队列深度、任务等待、Worker 租约和重试次数。
- 每种工作流的完成、失败、取消、过期和局部恢复率。
- 工具成功率、参数校验失败、超时和副作用重复率。
- 检索 Recall 代理指标、引用支持失败和证据不足比例。
- 模型 token、单次成本、按用户和工作流的成本。
- 文件上传、解析、索引、删除的耗时和失败原因。
- 关键前端事件：恢复成功、提交成功、保存冲突、审批结果和用户反馈。

日志分为业务审计日志和技术调试日志，默认脱敏。原始模型输入输出按最小必要原则保存并设置访问权限与保留周期。

### 20.3 服务目标

首发目标先使用可测量的相对门槛，正式 SLA 在内测数据后固化：

- 已提交的用户作答和审批决定不丢失。
- 运行终态与任务中心最终一致。
- 核心用户 API 月度可用性目标不低于 99.5%。
- SSE 断线后自动恢复；服务端事件无序列缺口。
- 任何重复副作用都能通过幂等审计发现。

## 21. 产品指标和运营指标

### 21.1 北极星方向

“每周完成的可验证学习闭环数”和“薄弱知识点在后续独立验证中的改善率”比聊天次数和停留时长更重要。

### 21.2 用户指标

- 首次诊断完成率。
- 提问到讲解完成率。
- 讲解到验证题启动率。
- 练习提交率和作答保存成功率。
- 错因确认率。
- 到期复习完成率。
- 后续独立验证正确率提升。
- 计划任务完成率和跳过率。
- 用户主动纠错、举报和删除行为。

### 21.3 Agent 指标

- 运行完成率、局部重试成功率、恢复成功率、取消延迟。
- 正确引用率、虚假引用率、证据不足降级率。
- 题目来源标签和题型判断准确率。
- 客观批改准确率、主观评分点覆盖率。
- 越权、提示注入和敏感信息泄露事件。
- p95 延迟、每闭环成本和异常 token 消耗。

### 21.4 不作为成功指标

- 聊天消息数量。
- 平均会话时长。
- Agent 输出文字长度。
- 没有证据的掌握百分比增长。

## 22. 分阶段路线图

### Phase 0：契约和骨架，P0

- 用户身份和 `/api/v1/app/*` 边界。
- `agent_threads`、`agent_runs`、`agent_steps`、`agent_events` 最小模型。
- SSE 快照、断点续传和任务中心。
- 公共检索门面和资源归属测试。
- 用户端去除对 Agent 核心流程的 fixture 依赖。

完成标准：创建运行、刷新恢复、取消、幂等和权限隔离均有自动测试。

### Phase 1：提问到验证，P0

- `explain`、`validate`、客观题练习和提交。
- 引用面板、来源等级和证据不足降级。
- 题目快照、练习记录和基础学习事件。
- J1、J2、J7 和 FQ-01/FQ-02 验收。

### Phase 2：错题到复习，P0

- 客观批改、错因候选和用户确认。
- 复习调度、掌握状态和错题页面。
- J3、J8 和 FQ-05/FQ-06 质量门禁。

### Phase 3：今日计划和学习地图，P1

- 用户档案、诊断、目标、今日任务和掌握地图。
- 计划草稿、差异预览、审批、版本和撤销。
- J6 验收。

### Phase 4：管理端 Agent 运营和评测，P0/P1

- Agent Run 详情、错误检索和安全摘要。
- 数据集、固定 fixture、批量评测、结果对比和发布门禁。
- 人工评分与回归案例沉淀。
- 首发前至少完成 E01-E08。

### Phase 5：用户资料，P1

- 文件上传、扫描、MinerU/文本解析、向量索引和删除。
- 用户资料授权选择、来源分层和多模态展示。
- J4、资料隔离和删除验收。

### Phase 6：按需客户端增强，P2

- PWA、Tauri 或浏览器扩展只在真实数据证明需要时建设。
- 首个桌面切片仅覆盖“授权目录、用户确认、上传索引、在线程引用”。
- 不因为桌面化而开放通用命令执行。

## 23. 验收标准

### 23.1 用户端验收

- 用户可以完成“提问、讲解、验证题、提交、错因、复习任务”闭环。
- 切页、刷新和 SSE 断线不丢失运行状态或学习事实。
- 客观题判定准确，主观题明确为 AI 辅助反馈。
- 原题、平台题、AI 题、用户资料和模型推断标签不混淆。
- FQ-01 至 FQ-07 在桌面和移动端无题干、图片、选项、公式和操作控件重叠。
- 用户可查看、拒绝、撤销或删除可控的长期影响动作。

### 23.2 管理端验收

- 可按用户、工作流、版本、状态、时间查看 Agent Run。
- 可查看每一步安全摘要、工具结果、错误、引用、成本和版本。
- 可创建评测数据集和案例，运行固定版本回归。
- 可进行人工评分、标注问题并转为回归案例。
- 质量门禁支持阻断发布，且发布历史可审计。
- 管理员查看用户内容按角色和理由审计。

### 23.3 后端和 Agent 验收

- 所有用户资源经过 `user_id` 归属校验，跨用户访问自动测试为零通过。
- 所有副作用写入支持幂等，重复提交不产生重复练习、计划或审批结果。
- 工具输入输出经过 Schema 校验，超时、重试、取消和恢复状态可观测。
- 已成功的工具结果不会因后续 LLM 失败而丢失。
- 审批前不发生长期写入，审批拒绝保持原计划不变。
- 引用必须指向真实且当前用户可见的来源；虚假引用为发布阻断项。
- 用户资料删除后不参与新检索，异步删除有可追踪终态。
- 核心评测集通过发布门禁，且没有安全类 0 容忍问题。

## 24. 风险和处理策略

| 风险 | 影响 | 处理 |
|------|------|------|
| Agent 自由度过高 | 越权、不可复现、成本失控 | 固定工作流、工具白名单和状态机 |
| 资料注入 Prompt | 错误工具调用或泄露 | 不可信内容分层、服务端权限复核 |
| RAG 引用不可靠 | 用户被错误知识误导 | 证据门禁、引用校验、人工回归集 |
| 生成题质量不足 | 练习错误、用户失去信任 | 题目质量规则、审核状态和减少题量 |
| 掌握度虚高 | 计划错误、学习效果下降 | 事实事件、间隔验证、证据可解释 |
| 长任务状态丢失 | 用户重复操作或任务消失 | 持久化事件、检查点、幂等和恢复 |
| 模型供应商波动 | 延迟和成本上升 | 超时、fallback 策略、局部重试、预算 |
| 用户资料泄露 | 严重隐私和合规风险 | 资源过滤、隔离索引、签名 URL、删除流程 |
| 管理员只看平均分 | 高风险个案漏检 | 0 容忍安全门禁、分层指标和人工抽样 |
| 过早桌面化 | 交付分散、权限风险 | Web-first，按真实需求触发 |

## 25. 未决事项和决策规则

以下事项不阻塞 Phase 0，但必须在对应阶段进入决策记录：

1. 对象存储使用现有部署还是引入 S3 兼容服务。决策依据是文件规模、备份和删除能力，不以本地路径作为用户 API 契约。
2. Agent Worker 使用现有 Redis 队列还是引入专用工作流引擎。若需要跨进程 durable execution、checkpoint 和 replay，优先选择已有成熟实现并保持领域工具协议不变。
3. 复习调度器是否采用 FSRS 等成熟算法。先用版本化规则实现可回放，再用离线和线上数据验证替换收益。
4. 是否采用 MCP adapter。MCP 的 tools、resources、prompts 和授权边界可作为未来互操作层；首发内部工具协议不直接把所有平台能力暴露为 MCP。
5. 是否增加 Tauri 或浏览器扩展。只有当本地资料或网页选区任务达到明确频率和失败率阈值才立项。

任何新工具或新 Agent 自主能力必须回答：用户价值是什么、权限级别是什么、失败如何恢复、是否有幂等键、如何评测、如何撤销、如何审计。不能只因为模型“能调用”就加入生产工具集。

## 26. 前沿方案研究与参考

本 PRD 参考公开官方资料和可验证的通用工程模式，不依赖所谓 Claude Code 泄露源码。

### Anthropic

- [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)：区分 workflows 与 agents，强调从简单、可组合、可观测的方案开始，并使用程序化质量门禁。
- [Claude Code overview](https://code.claude.com/docs/en/overview)：公开说明其可以读取代码库、编辑文件、运行命令并集成开发环境。本项目只借鉴“工具、权限、任务状态和可观察执行”的产品模式，不把代码编辑能力照搬到学习场景。

### OpenAI

- [Agents guide](https://developers.openai.com/api/docs/guides/agents)：参考 Agent、工具、编排和运行追踪的公开设计方向；本项目仍以自身学习域状态机和权限边界为准。

### LangGraph

- [Durable execution](https://docs.langchain.com/oss/python/langgraph/durable-execution)：参考持久执行、检查点、恢复和副作用幂等；本项目不因使用该思想而把业务事实交给图框架隐式管理。

### Model Context Protocol

- [MCP specification 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18)：参考 tools、resources、prompts、能力协商和授权安全边界。首发只保留未来 adapter 的兼容空间。

### 研究结论

这些方案共同支持以下产品选择：先做确定性、可恢复、可测试的学习工作流；让模型在窄范围内做决策；对工具输入输出做结构化校验；把审批、审计和评测作为生产系统的一部分；用真实学习结果和安全可靠性衡量 Agent，而不是用输出长度或自由度衡量 Agent。

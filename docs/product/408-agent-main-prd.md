## 1. 文档目的

本文件是 408 学习 Agent 主体建设的产品契约。它回答以下问题：

1. 用户如何从提问进入讲解、练习、批改、错因确认和复习，而不是停留在一次性聊天。
2. Agent 在什么范围内可以自主选择工具，什么动作必须经过用户审批。
3. 用户如何观察、取消、重试和恢复长任务，以及异常时预期看到什么结果。
4. 平台知识、用户上传资料、用户长期学习状态和模型推断应如何隔离并被正确引用。
5. 学习进度如何由可追溯事实聚合，而不是由 Agent 随意写入一个百分数。
6. 管理员如何查看真实运行、标注问题、维护评测集，并在模型、Prompt 或工具变更前执行回归门禁。

本 PRD 不替代数据库迁移方案、详细 UI 规格或单个模块的工程设计。Agent Runtime 的数据模型、API/SSE、Worker、事务、恢复、工具 Schema、可观测性和测试方案以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md)为准。接口和字段可以细化，但不能违反本文定义的用户可感知状态、资源归属、权限、可撤销性和可靠性要求。

## 2. 决策摘要

### 2.1 产品定位

产品是一个 **408 学习工作台**，不是普通聊天页、知识库和刷题工具的简单拼接。对话是用户发起任务的入口，学习任务、练习集、错因报告、复习任务和计划版本才是可持续的产品对象。

首发主闭环：

```text
用户提问
  -> 意图识别和上下文确认
  -> 受约束检索与引用
  -> 结构化讲解
  -> 用题验证
  -> 作答和批改
  -> 错因确认
  -> 生成可撤销的复习任务
  -> 后续间隔复习和掌握状态更新
```

### 2.2 Agent 形态

采用“外层确定性学习工作流 + 内层受约束 Agent 探索”的混合方案：

- 确定性代码负责学习主流程、状态转换、权限检查、题目快照、学习事实写入、复习调度及所有高风险动作边界。
- LLM 在授权的低风险阶段负责自然语言意图解析、查询改写、有限范围内的只读探索、解释生成、错因候选和主观题评分辅助。
- 探索可以根据已获得的信息选择下一次允许的读取动作，但不能改变权限、审批、长期写入、重试次数或业务主流程；实现与恢复语义见[Agent 工作流编排技术设计](../tech/408-agent-workflow-orchestration-design.md)。
- 每项可用能力都有明确版本、授权范围、失败处理和审计要求。
- Agent 只能通过受控领域能力影响学习结果，不能任意读写平台数据或执行系统操作。
- 长期计划、影响较大的个人数据修改和外部动作必须经过明确审批。
- 第一版不提供通用 Shell、任意本地命令、自由多 Agent 协作或无审批的长期写入。

### 2.3 端与服务边界

- 第一版采用响应式 Web，继续复用现有 React + Vite 用户端。
- Agent Runtime、工具执行、检查点、事件、记忆和评测都运行在服务端。
- 用户端与管理端使用独立的服务入口和权限边界。
- 管理端新增 Agent 运行和评测能力，不与用户学习服务混用权限。
- 当前同步问答能力只作为过渡；新的用户 Agent 体验逐步迁移到可恢复的对话运行时，不继续向旧路径叠加 Agent 能力。

### 2.4 评测结论

管理端必须提供评测中心。Agent 能力不能只看最终答案的语言质量，而应同时评估意图路由、检索和引用、工具调用、学习闭环、恢复能力、题目质量、批改质量、安全和成本。离线评测是变更发布门禁，线上评测是监控和抽样，人工复核用于沉淀新回归案例。

### 2.5 可靠性结论

Agent 的唯一真实状态在服务端。客户端断线、刷新、切页或关闭浏览器都不能丢失已提交的用户动作和已完成结果；恢复与重试不能重复已经成功的学习动作。实现机制以技术设计为准。

## 3. 背景、问题和目标

### 3.1 当前问题

现有系统已经具备 408 学科、章节、知识点、题目、语料解析、问答和管理员内容运营能力，但用户学习闭环仍不完整：

- 用户端 Agent 页面仍大量依赖样例和本地状态，尚未反映真实对话运行和恢复结果。
- 当前问答模式同步返回一次回答，不能满足长任务、连续练习和恢复需求。
- 对话、作答、错因和掌握证据尚未构成统一、可回看的学习闭环。
- 用户资料和平台语料尚未形成清晰的权限隔离和引用分层。
- 管理端已有内容审核和对话观察能力，但没有 Agent 评测数据集、运行对比、人工标注和发布门禁。

### 3.2 产品目标

首发版本需要让真实用户稳定完成以下任务：

1. 询问一个 408 知识点，得到基于可靠来源的结构化讲解。
2. 从讲解一键进入 1 至 3 道验证题，不泄露尚未作答的答案。
3. 完成作答后得到结果、错因候选和后续复习建议。
4. 切页、刷新或短暂断网后，仍能恢复线程、练习和 Agent 运行。
5. 上传自己的 PDF、图片或笔记，并在个人范围内检索和引用。
6. 在 Agent 和学习进度页看到由真实学习证据支持的建议任务与阶段进度，而不是无依据的推荐分数。
7. 管理员能够发现错误引用、题目污染、工具失败和模型退化，并将问题转成回归用例。

### 3.3 非目标

首发不做：

- 通用办公或浏览器自动化 Agent。
- 任意网站、桌面软件或本地终端操作。
- 用户之间共享私有资料和社交社区。
- 完整网盘、笔记软件或课程直播系统。
- 无人工审核的正式题库自动发布。
- 用一次聊天、一题答对或模型主观判断直接宣布用户“已经掌握”。
- 以隐藏思维链为产品展示或评测对象。
- 以泄露代码为能力依据。Claude Code 仅参考其公开产品文档和可验证的工程模式。

## 4. 用户与使用场景

### 4.1 用户角色

| 角色 | 主要目标 | 核心风险 |
|------|----------|----------|
| 备考用户 | 理解知识、完成练习、改善薄弱点 | 误导性解释、重复题、进度失真、资料泄露 |
| 内容审核员 | 修正知识点、题目、来源和标签 | 误发布、来源丢失、审核状态不一致 |
| Agent 运营/评测员 | 观察运行、维护评测集、比较版本 | 只看平均分、无法复现、成本失控 |
| 系统管理员 | 管理用户、权限、模型和系统健康 | 越权、配置误操作、敏感数据暴露 |

### 4.2 关键用户任务

- “我不会这个知识点，请讲到我能做题。”
- “给我几道适合当前水平的题，不要把答案提前告诉我。”
- “我做错了，告诉我错在概念、条件、计算还是方法。”
- “根据最近的错误，今天最应该复习什么？”
- “把这份自己的讲义和平台知识结合起来，但要分清来源。”
- “为什么 Agent 做了这个动作？我能否拒绝或撤销？”

### 4.3 必须覆盖的异常场景

1. 检索没有足够证据。
2. 题库候选不足或题目质量被审核阻断。
3. 工具成功但后续模型超时。
4. 运行中用户刷新、切页、重复点击或多设备打开。
5. 用户拒绝计划修改或资料处理审批。
6. 主观题包含图片、公式、小问或 A/B/C/D 寄存器名称。
7. 用户上传恶意文件、提示注入内容或包含敏感信息。
8. 模型输出结构化 JSON 不合规、引用不存在或答案泄露。

## 5. 产品原则与体验约束

### 5.1 行动优先于聊天

每次 Agent 运行至少应有一个明确的结果类型：`explanation`、`practice_set`、`grading_report`、`mistake_diagnosis`、`review_task`、`plan_draft` 或 `source_summary`。纯文字回答可以存在，但在能形成下一步动作时，应提供结构化按钮或产物。

### 5.2 证据先于断言

回答中的内容必须区分：

- 平台知识库事实。
- 平台原题或审核题事实。
- 用户资料事实。
- Agent 基于证据的推断。
- 未被资料支持的通用模型知识。

没有足够证据时，Agent 必须明确说“平台资料不足”，可以询问澄清或提供标记为推断的辅助说明，禁止伪造来源、页码、题号、答案或题库状态。

### 5.3 状态真实且可恢复

“正在处理”必须对应服务端真实运行。客户端不能因为 SSE 连接断开就把任务标成失败，也不能因为重新挂载组件就重复提交。

### 5.4 高风险写入可解释、可撤销

审批面板必须展示动作、原因、影响范围、变更前后差异和撤销方式。审批前不产生长期写入；审批通过后必须保留可追溯的决定记录。

### 5.5 不暴露隐藏思维链

用户看到的是安全的行动摘要、工具状态、来源、结果和下一步，不是模型逐 token 推理或内部提示词。管理员看到的是可审计的 action trace、工具输入输出摘要、错误码、版本和结果证据，不以“思维链越长越好”衡量 Agent。

## 6. 产品与实现边界

首发是响应式 Web 学习工作台。用户端只使用用户 API，管理端只使用管理 API；服务端负责 Agent 的真实运行状态、权限和结果。用户刷新、断线或切页不能改变已提交动作的真实性。

实现采用现有平台能力并逐步新增 Agent、工作区、学习、练习、用户资料和评测模块。模块归属、依赖方向、旧 `/api/v1/chat` 的迁移、运行拓扑和存储职责以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#4-总体拓扑)为准。产品侧的硬规则是：Agent 只能通过受控领域能力产生学习结果，不能自由访问数据表、系统命令或其他用户资料。

## 7. 用户端 PRD

### 7.1 信息架构

一级导航固定为：

1. Agent：线程、运行状态、引用和结构化产物。
2. 练习：专项、智能组卷、错题重练、模拟和历史会话。
3. 薄弱点：错因聚类、待复习队列、再次验证和基于学习证据的复习建议。
4. 学习进度：408 学科、章节、考点、掌握证据、阶段进度、学习计划和推荐任务。
5. 资料：用户资料、解析状态、来源和删除管理。

账户设置、隐私、数据导出、模型使用说明和通知设置放到账户菜单。

### 7.2 页面需求

#### U-01 Agent 首页与任务建议，P0

展示：继续未完成运行、最近完成产物、推荐学习任务、任务预计时长、推荐原因和待复习薄弱点。

行为：

- `开始` 创建或恢复对应任务，不重复创建运行。
- `跳过` 记录用户行为，并重新计算推荐任务。
- `调整建议` 只影响任务排序或草稿；影响长期周计划时进入审批。
- `继续` 回到最近一个可恢复的线程或练习会话。

验收：每条推荐都能展开到目标、薄弱点、掌握证据或计划约束中的至少一项；无学习记录的新用户显示“需要诊断”而非虚构掌握度。

#### U-02 Agent 工作区，P0

组成：线程列表、消息时间线、运行步骤摘要、引用面板、结构化产物、输入框、任务状态中心入口。

支持模式：问懂知识点、分析题目、生成验证题、复盘错误、制定计划、处理用户资料。自然语言可以自动路由，但必须允许用户在发送前选择模式，或在歧义时先澄清。

每条消息和由它触发的运行必须有明确关联。一个用户消息可以触发一个主运行；重试必须展示为原运行的继续或关联操作，不得伪装为新的无关联对话。

#### U-03 运行详情与任务中心，P0

展示运行状态：排队、规划、执行、等待用户、等待审批、完成、失败、取消或过期。

展示安全摘要：正在检索的范围、已找到几项候选、已生成几道题、等待什么输入、失败步骤和下一步选择。禁止显示隐藏 Prompt 和原始思维链。

操作：取消运行、重试失败步骤、从检查点继续、打开产物、回答澄清问题、处理审批。

#### U-04 引用与来源，P0

每条引用显示来源层级、标题、页码或题号、关联知识点、来源状态和可展开原文。来源层级至少包括：平台知识、平台原题、平台练习题、我的资料、模型推断。

引用打开失败时显示来源暂不可用，不回退成无来源的确定性表述。每条引用都应有稳定的来源定位信息，能够定位到资料片段、页码、题号或本次练习题面。

#### U-05 练习工作区，P0

支持选择题、判断题、填空题和主观题基础形态。主观题支持分小问草稿、图片展示、公式文本和自动保存；第一版不承诺完全可靠的数学公式编辑器，可先使用文本/Markdown 输入。

练习题必须在创建会话时保存快照，包括题干、选项、题型、答案版本、解析版本、来源标签、关联考点和资源引用。题库后续变更不得修改历史答题上下文。

未提交练习不展示正确答案。提示分层为方向提示、关键概念提示、解法提示，使用情况写入作答证据。

#### U-06 批改、错因与复习，P0

提交后先返回批改状态和客观结果；深度批改可以异步运行。用户能确认或拒绝错因候选，也能选择“无法判断”。

系统默认错因枚举：概念混淆、条件遗漏、计算错误、解题策略不熟、审题错误、知识未覆盖、表达不完整、时间管理。错因是可修正标签，不是人格判断。

错题只有经过后续验证和复习规则满足后，才能从待复习队列移出。查看答案、收藏或标记“已理解”不能直接改变掌握状态。

#### U-07 薄弱点，P0

按错因、知识点和复习状态聚合薄弱点，显示待复习队列、最近错误、再次验证结果和改善趋势。支持从薄弱点进入讲解、专项练习和复习。

#### U-08 学习进度，P1

按学科、章节、知识点显示掌握状态和证据：近期正确率、答题次数、提示使用、最近复习时间、待处理薄弱点和平台考频；同时展示当前阶段、学习计划和基于证据生成的推荐任务。支持从节点进入讲解、专项练习和薄弱点。

#### U-09 资料，P1

支持主动上传 PDF、图片、Markdown/纯文本，显示上传、解析、切块、索引和失败状态。用户能删除资料、查看处理范围、知道资料是否会被发送给模型，并能在会话内选择是否使用。

平台资料和个人资料始终分开显示；个人资料默认仅当前用户可访问，不参与平台知识库、不参与其他用户检索。

#### U-10 账户、隐私和数据控制，P0

提供会话管理、已登录设备、导出个人学习数据、删除用户资料、删除线程和申请删除账号。隐私说明必须解释：上传文件存储位置、解析链路、模型调用范围、保留时间和删除延迟。

### 7.3 用户端状态和交互门禁

所有 P0 页面至少设计并实现以下状态：空状态、加载、局部加载、运行中、等待用户、等待审批、完成、部分完成、失败、取消、权限不足、资源删除和网络断开恢复。

移动端要求：

- 运行时间线、引用、审批和题目内容不得互相覆盖。
- 长题干、公式、图片和答案区必须自然换行或纵向滚动。
- 练习输入控件在键盘弹出时仍能提交和保存。
- 桌面三栏在窄屏切换为主内容加抽屉，不把三栏强行缩小。

## 8. Agent 学习工作流

### 8.1 工作流优先级

首发工作流：

| 用户任务 | 触发 | 长期影响 | 级别 |
|----------|------|----------|------|
| 讲解知识点或题目 | 用户提问 | 生成可回看的讲解与引用 | P0 |
| 用题验证 | 用户点击验证 | 创建练习；提交后形成作答证据 | P0 |
| 批改与错因复盘 | 用户提交答案或请求复盘 | 产生批改结果和待确认错因 | P0 |
| 复习 | 到期或用户主动发起 | 形成复习证据和后续建议 | P0 |
| 制定或调整计划 | 首次诊断或用户调整 | 草稿可自动生成，长期计划需审批 | P1 |
| 使用个人资料 | 用户上传或在会话中授权 | 仅改变当前资料处理或检索范围 | P1 |
| 查看阶段报告 | 用户查看进度 | 只读聚合 | P1 |

### 8.2 标准解释工作流

```text
接收问题
  -> 确认学习目标和必要上下文
  -> 在授权范围内寻找可靠资料
  -> 生成带来源的结构化讲解
  -> 证据不足时明确说明
  -> 提供验证、追问和收藏动作
```

讲解必须能关联真实且当前用户可见的来源；核心结论没有足够证据时，必须降级为“证据不足”或请求补充信息，不能静默输出。

### 8.3 验证题工作流

```text
确定需要验证的知识点和当前水平
  -> 选择来源清晰、质量合格且未泄露答案的题目
  -> 固化为本次练习内容
  -> 返回可作答的练习
```

默认优先使用审核通过的原题或平台题。题目不足时可以生成 AI 练习题，但必须标注 `ai_generated`，不写入正式原题库；生成题必须通过答案一致性、题型一致性、知识点覆盖和重复性检查。

### 8.4 批改工作流

- 客观题依据本次练习固化的答案规则判定，模型不拥有最终答案判定权。
- 填空题优先按明确规则归一化；存在歧义时进入复核。
- 主观题只提供评分点、依据与缺失点的 AI 辅助反馈，不伪装成官方阅卷。
- 用户可回看批改结论的题面、答案依据和来源。

### 8.5 Agent 动态决策的边界

LLM 可以在白名单内选择检索、读取用户状态、组织题目、生成解释和生成错因候选。以下决策由代码固定：

- 当前用户是否有权限访问资源。
- 题目是否可以被使用。
- 客观题正确答案。
- 学习结果何时影响进度与掌握状态。
- 是否需要审批。
- 幂等、重试、超时、取消和状态转换。
- 任何外部发送、删除和高风险本地动作。

## 9. Agent 能力与授权

首发 Agent 可以帮助用户：读取当前学习上下文和已授权资料、检索平台知识和题目、生成讲解与未提交练习、批改作答、提出错因候选、创建可撤销复习建议，以及生成计划变更草稿。

用户应能理解并控制以下边界：

| 动作类别 | 产品策略 |
|----------|----------|
| 查找资料、读取当前学习状态、生成讲解或练习草稿 | 可自动执行，但仅限当前用户有权访问的内容。 |
| 确认错因、提交作答、创建复习任务 | 由用户动作触发，或按既定规则自动创建且可撤销。 |
| 修改长期计划、归档错题、批量调整学习目标 | 必须先展示影响和差异，并等待明确审批。 |
| 外发资料、执行本地命令、读取任意本地路径、任意浏览器自动化 | 首发不提供。 |

工具失败、重试和权限判断不能给用户制造重复动作或不确定结果。用户得到的是安全的动作摘要、结果、来源和下一步；实现采用的工具注册、Schema、重试和审计协议见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#8-模型工具与引用)。

## 10. 运行、恢复与对话连续性

用户可见的运行状态包括：排队、处理中、等待补充信息、等待审批、完成、失败、取消和过期。页面必须清楚显示当前等待的用户动作、已完成的结果、失败原因和可采取的下一步。

- 刷新、切页、SSE 断线或短暂网络中断后，用户可回到同一线程继续查看真实状态与已完成产物。
- 重试应保留此前已完成的讲解、检索或练习结果；重复点击发送、提交、审批或取消不得制造重复学习记录。
- 取消只停止尚未完成的工作，不抹除用户已提交的消息、作答或已经生成的可用结果。
- 对过期审批、资料已删除或多设备修改冲突，系统必须明确说明原因并要求用户重新处理，而不是静默覆盖。

状态机、持久化事件、检查点、上下文压缩和 SSE 断点续传的实现见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#6-状态机租约与恢复)与[HTTP 与 SSE 契约](../tech/408-agent-conversation-runtime-design.md#9-http-与-sse-契约)。

## 11. 学习域与进度更新

### 11.1 以学习证据更新进度

Agent 不能凭一次聊天、单次答对或模型主观判断把用户标记为“已掌握”。学习进度应基于可回看、可解释的学习证据，例如独立作答、近期正确率、提示使用、评分点覆盖、间隔复习和再次验证。

首发状态面向用户表达为未开始、学习中、需要巩固、接近掌握、已掌握和证据不足。一次答对可以改善状态，但不能单独从未学习跳到已掌握。用户明确标注“我已掌握”是用户偏好或覆盖意见，必须与系统依据分开显示。

### 11.2 哪些动作影响长期进度

| 用户动作或结果 | 产品规则 |
|----------------|----------|
| 查看讲解、收藏或标记“已理解” | 可以影响推荐和后续提示，但不直接证明掌握。 |
| 提交客观题或完成一次验证 | 形成可用于进度判断的作答与结果证据。 |
| 生成错因候选 | 仅作为待确认建议，不把候选当成用户的真实错因。 |
| 用户确认、修改或拒绝错因 | 更新错因记录，并影响后续薄弱点和复习建议。 |
| 创建复习建议 | 可按既定学习规则自动出现，但用户可以撤销或调整。 |
| 修改长期计划、归档错题 | 必须由用户明确操作或审批，不能被对话自动改写。 |

学习事实、聚合读模型、调度版本和命令幂等的实现见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#56-学习资料和评测域持久化接口)与[工作流编排技术设计](../tech/408-agent-workflow-orchestration-design.md)。

## 12. 练习、批改、错题和复习

### 12.1 题目来源和质量等级

题目必须具备来源标签：

- `platform_original`：平台审核的原题或官方来源题。
- `platform_adapted`：平台基于原题改编并审核的题。
- `ai_generated`：模型生成、尚未成为正式题库事实的练习。
- `user_source`：用户资料中的题目。

FQ-01 至 FQ-07 继续作为首发验收和回归用例，特别验证：选项恢复、主观题识别、公式图片、低质量题阻断和生成题来源标记。

### 12.2 题目选择门禁

组题前必须过滤：审核未通过、结构不完整、答案缺失、解析冲突、来源不可追溯、重复度过高和已被质量规则阻断的题目。候选不足时减少题量或明确告知用户，不为凑数量降低质量门槛。

### 12.3 作答连续性

开始练习后，用户看到的题面、选项、答案依据和批改规则必须在本次会话内保持一致，不能因题库后续修订而改变已提交结果。多设备编辑同一答案时，系统必须提示冲突并让用户选择，不得静默丢失较新的作答。

### 12.4 错因和复习

Agent 输出错因候选时必须关联作答证据，例如用户遗漏的条件、错误计算步骤或未覆盖评分点。用户可确认、修改、拒绝或标为无法判断。

复习建议依据错误严重程度、历史间隔、提示使用和再次验证结果产生。复习日期不能由模型任意决定；调度规则的具体实现可演进，但同一规则下的建议必须可解释且可复现。

练习快照、作答冲突、确定性批改、错因确认和复习调度的实现见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#56-学习资料和评测域持久化接口)与[工作流编排技术设计](../tech/408-agent-workflow-orchestration-design.md)。

## 13. 用户资料与多模态内容

### 13.1 用户可见规则

- 用户主动选择文件后上传，首发不扫描任意本地目录。
- 用户可以看到资料的上传、处理、可用、失败和删除进度，并在失败时得到下一步处理方式。
- 用户资料引用显示“我的资料”，不得显示成平台权威内容。
- 用户删除资料后，资料立即不参与新的 Agent 检索；系统完成清理后展示可查询的结果。
- 用户可以关闭某份资料在 Agent 中的使用，关闭只影响检索授权，不等于删除文件。

### 13.2 不可信内容防护

用户资料和检索文本均是不可信内容。资料中出现“忽略系统指令”“调用某工具”“发送文件”等内容时，只能作为学习材料展示，不能扩大 Agent 权限、改变审批要求或触发额外动作。

资料处理、检索隔离、删除、内容安全和引用实现见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#85-用户资料处理与删除)与[安全隐私和审计](../tech/408-agent-conversation-runtime-design.md#11-安全隐私和审计)。

## 14. 管理端 PRD

### 14.1 现有入口保留

现有 Dashboard、Knowledge、Questions、Corpus/Outline、Review、Search Debug、Conversations、Crawler、Monitor、Settings、Users 继续保留。它们仍负责平台知识、题库、语料解析、审核、系统监控和管理员用户。

### 14.2 新增 Agent 运营入口

| 路由 | 作用 | 优先级 |
|------|------|--------|
| `/admin/agent-runs` | 按状态、用户、工作流、模型、版本和时间筛选真实运行 | P0 |
| `/admin/agent-runs/:id` | 查看安全 action trace、step、tool、事件、引用、错误和成本 | P0 |
| `/admin/evals` | 评测总览、发布门禁和近期回归 | P0 |
| `/admin/evals/datasets` | 数据集版本、案例和标签管理 | P0 |
| `/admin/evals/runs` | 发起、排队、取消和比较评测运行 | P0 |
| `/admin/evals/runs/:id` | 案例结果、指标、版本差异和失败详情 | P0 |
| `/admin/evals/cases` | 案例详情、预期行为、禁止行为和回归标记 | P0 |
| `/admin/evals/annotations` | 人工复核、评分、问题标签和证据引用 | P1 |
| `/admin/agent-config` | Prompt、模型、工具和工作流版本 | P1 |
| `/admin/quality-gates` | 发布阈值、豁免审批和门禁历史 | P1 |

### 14.3 Agent Run 详情

管理员可以查看：

- 用户、线程、运行模式、状态和耗时。
- 模型配置、Prompt 版本、工具版本和数据集版本。
- step 时间线、工具调用输入输出摘要、重试、超时、错误码和检查点。
- 引用实体、页码、召回分数、引用支持检查结果。
- 产生的练习、批改报告、计划草稿和学习命令。
- token、模型成本、队列等待和下游服务耗时。

管理员默认不能查看不必要的完整用户原文。敏感内容按权限脱敏；访问完整内容必须有审计理由。

### 14.4 评测入口为什么必须在管理端

Agent 的质量会随模型、Prompt、检索索引、题库、工具实现和策略变更而变化。没有后台评测入口，就无法复现线上问题、比较版本或阻止质量退化。评测中心不是面向用户显示一个“Agent 总分”，而是内部质量控制设施。

管理端必须支持：固定状态运行、模拟工具返回、模型和 Prompt 版本锁定、批量运行、逐案例结果、人工标注、结果对比、回归集沉淀和发布门禁。

### 14.5 内容质量联动

评测发现错误引用、题型误判、答案泄露或题目质量问题时，管理员可以从运行详情跳转到对应知识点、题目或语料审核页，创建质量问题并将案例加入评测集。评测案例和内容审核状态分开保存，不能用“评测通过”替代“题目审核通过”。

## 15. Agent 评测体系

评测中心服务于质量控制，而不是给用户展示一个“Agent 总分”。它必须同时使用发布前回归、线上脱敏观察和人工复核，分别验证：回答是否有依据、引用和题目来源是否可信、学习建议是否遵守用户授权、长任务是否可恢复，以及产品是否安全可靠。

任何被发现的错误引用、题型误判、答案泄露、题目质量问题或不当行为都应能进入复现与回归流程。线上数据未经审查不能直接用于训练或发布判断；不得使用隐藏思维链长度、拟人程度或单一总体分数代表 Agent 质量。

安全、越权、答案泄露、虚假引用、资料隔离失败、审批前长期变更和重复副作用属于发布阻断问题。完整的评测维度、固定案例、质量阈值和工程门禁以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#13-测试与发布门禁)为准。

## 16. 数据归属和产品契约

所有线程、消息、运行、练习、作答、错题、学习计划、资料、笔记和评测记录必须有明确归属。用户只能查看和操作自己的资源；管理员仅在职责和权限允许时查看必要的脱敏信息。

对话、作答、错因确认、复习和计划变更各自保留可解释的来源。模型推断不自动成为长期记忆或掌握事实；仅在用户明确表达、确有稳定学习价值、可解释且可删除时，才可保存为用户偏好。健康、未成年人、身份和政治等敏感属性不作为默认学习画像。

具体领域表、字段、引用关系、事件、版本和删除墓碑以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#5-核心对象与数据模型)为准。

## 17. 用户与管理端服务约束

用户端通过经过认证的用户服务完成线程、运行、练习、薄弱点、学习进度和资料操作。用户无需等待长任务完成即可回到工作台；服务必须返回可理解的当前状态、可执行动作和安全错误说明。资源不存在、权限不足、资料尚不可用、证据不足、冲突、限流与暂时故障都要以明确状态呈现，不能把内部错误或其他用户资料暴露给用户。

管理端与用户端使用独立权限边界。管理员的运行重放、问题复现与评测只生成隔离的评测结果，绝不能因查看或重放真实运行而再次提交用户作答、变更计划、删除资料或写入其他用户学习事实。

路由、请求响应、SSE、错误码、幂等和管理端 replay 的技术契约见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#9-http-与-sse-契约)。

## 18. 安全、隐私和滥用防护

用户对自己的线程、资料、练习和学习记录拥有查看、导出和删除控制权；任何跨用户资源访问均不可接受。用户端与管理端权限独立，管理员只在职责需要时查看最少信息，并对受限内容访问留痕。

用户上传内容、检索文本和模型输出都不可信。它们不能改变系统规则、扩大工具权限、触发命令执行或要求外发资料。首发不提供任意本地路径读取、命令执行、外发资料和浏览器自动化；学习产品不输出人格、医疗或心理诊断。

产品不得向用户暴露密钥、系统提示、内部地址、数据库错误、供应商原始错误或其他用户内容。资料删除请求提交后，资料立即不再用于新检索，系统应显示后续清理状态并按照数据保留策略处理可删除副本。

资源授权、文件安全、限流、审计、日志脱敏和删除执行以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#11-安全隐私和审计)为准。

## 19. 可靠性、故障处理和可观测性

下列情况必须有清楚、可恢复的用户体验：

| 情况 | 用户应看到的结果 |
|------|------------------|
| 实时更新中断或刷新页面 | 可以重新进入同一线程，看到真实进度和已完成结果。 |
| 当前生成或检索失败 | 说明当前步骤未完成；已获得的可靠结果保留，并提供重试或继续路径。 |
| 证据不足或检索不可用 | 明确说明无法可靠回答，不把缓存、猜测或模型推断伪装为来源。 |
| 可用题目不足 | 返回实际可用题量和原因，不为凑数量降低题目质量。 |
| 重复点击、取消或恢复 | 不产生重复练习、计划、审批结果或学习记录。 |
| 审批过期、资料删除或多设备冲突 | 说明原因，保留用户可理解的现状，并要求重新处理或选择版本。 |

已经提交的作答和审批决定不得丢失；运行完成后的结果与工作台最终一致。追踪、告警、SLO、恢复、事件投递和故障演练以[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#12-可观测性与运维)为准。

## 20. 产品指标和运营指标

### 20.1 北极星方向

“每周完成的可验证学习闭环数”和“薄弱知识点在后续独立验证中的改善率”比聊天次数和停留时长更重要。

### 20.2 用户指标

- 首次诊断完成率。
- 提问到讲解完成率。
- 讲解到验证题启动率。
- 练习提交率和作答保存成功率。
- 错因确认率。
- 到期复习完成率。
- 后续独立验证正确率提升。
- 计划任务完成率和跳过率。
- 用户主动纠错、举报和删除行为。

### 20.3 质量守护指标

- 用户认为引用、题目来源、批改或错因不可信的反馈率。
- 讲解后进入验证、后续独立验证改善和复习完成情况。
- 用户恢复运行、撤销建议、处理冲突和删除资料是否成功。
- 安全、越权、答案泄露、虚假引用和资料隔离问题的发现与阻断情况。

运行延迟、队列、重试、工具、模型、token、成本与技术质量指标由[可观测性与运维](../tech/408-agent-conversation-runtime-design.md#12-可观测性与运维)和[测试与发布门禁](../tech/408-agent-conversation-runtime-design.md#13-测试与发布门禁)维护。

### 20.4 不作为成功指标

- 聊天消息数量。
- 平均会话时长。
- Agent 输出文字长度。
- 没有证据的掌握百分比增长。

## 21. 分阶段路线图

### Phase 0：契约和骨架，P0

- 用户可以创建线程、发送问题、查看运行状态并在刷新后继续。
- 工作台展示真实线程和任务状态，不以 fixture 冒充已实现能力。
- 用户资料、对话和学习记录遵守资源归属与隐私边界。

完成标准：用户可以可靠地提问、取消和恢复，且不会看到其他用户资源。

### Phase 1：提问到验证，P0

- 提问、可信讲解、验证题、客观题练习和提交。
- 引用面板、来源等级和证据不足降级。
- J1、J2、J7 和 FQ-01/FQ-02 验收。

### Phase 2：薄弱点到复习，P0

- 客观批改、错因候选和用户确认。
- 薄弱点聚合、复习调度、掌握状态和薄弱点页面。
- J3、J8 和 FQ-05/FQ-06 质量门禁。

### Phase 3：学习进度与学习计划，P1

- 用户档案、诊断、目标、学习计划、推荐任务和掌握地图。
- 计划草稿、差异预览、审批、版本和撤销。
- J6 验收。

### Phase 4：管理端 Agent 运营和评测，P0/P1

- Agent Run 详情、问题检索和安全摘要。
- 数据集、固定 fixture、批量评测、结果对比和发布门禁。
- 人工评分与回归案例沉淀。
- 首发前至少完成 E01-E08。

### Phase 5：用户资料，P1

- 文件上传、资料处理、引用与删除。
- 用户资料授权选择、来源分层和多模态展示。
- J4、资料隔离和删除验收。

### Phase 6：按需客户端增强，P2

- PWA、Tauri 或浏览器扩展只在真实数据证明需要时建设。
- 首个桌面切片仅覆盖“授权目录、用户确认、上传索引、在线程引用”。
- 不因为桌面化而开放通用命令执行。

## 22. 验收标准

### 22.1 用户端验收

- 用户可以完成“提问、讲解、验证题、提交、错因、复习任务”闭环。
- 切页、刷新和 SSE 断线不丢失运行状态或学习事实。
- 客观题判定准确，主观题明确为 AI 辅助反馈。
- 原题、平台题、AI 题、用户资料和模型推断标签不混淆。
- FQ-01 至 FQ-07 在桌面和移动端无题干、图片、选项、公式和操作控件重叠。
- 用户可查看、拒绝、撤销或删除可控的长期影响动作。

### 22.2 管理端验收

- 可按用户、工作流、版本、状态、时间查看 Agent Run。
- 可查看每一步安全摘要、工具结果、错误、引用、成本和版本。
- 可创建评测数据集和案例，运行固定版本回归。
- 可进行人工评分、标注问题并转为回归案例。
- 质量门禁支持阻断发布，且发布历史可审计。
- 管理员查看用户内容按角色和理由审计。

### 22.3 后端和 Agent 验收

实现发布前必须通过[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#13-测试与发布门禁)中定义的自动化、隔离、恢复和安全门禁。任何越权访问、审批前长期写入、客观题最终判定错误、重复副作用、虚假引用、资料隔离失败或安全类 0 容忍问题都阻断发布。

## 23. 风险和处理策略

| 风险 | 影响 | 处理 |
|------|------|------|
| Agent 自由度过高 | 越权、不可复现、成本失控 | 外层工作流固定业务边界，内层探索限制工具、回合、预算和出口 |
| 资料注入 Prompt | 错误工具调用或泄露 | 不可信内容分层、服务端权限复核 |
| RAG 引用不可靠 | 用户被错误知识误导 | 证据门禁、引用校验、人工回归集 |
| 生成题质量不足 | 练习错误、用户失去信任 | 题目质量规则、审核状态和减少题量 |
| 掌握度虚高 | 计划错误、学习效果下降 | 事实事件、间隔验证、证据可解释 |
| 长任务状态丢失 | 用户重复操作或任务消失 | 持久化事件、检查点、幂等和恢复 |
| 模型供应商波动 | 延迟和成本上升 | 超时、fallback 策略、局部重试、预算 |
| 用户资料泄露 | 严重隐私和合规风险 | 资源过滤、隔离索引、签名 URL、删除流程 |
| 管理员只看平均分 | 高风险个案漏检 | 0 容忍安全门禁、分层指标和人工抽样 |
| 过早桌面化 | 交付分散、权限风险 | Web-first，按真实需求触发 |

## 24. 未决事项和决策规则

以下产品决策不阻塞 Phase 0，但必须在对应阶段形成记录：

1. 复习调度是否采用成熟算法。任何替换都要证明能改善后续独立验证，且用户仍能理解建议来源并撤销不合适的安排。
2. 是否增加桌面应用或浏览器扩展。只有当本地资料或网页选区任务达到明确频率、失败率和用户价值阈值时才立项，且不得因为客户端扩展而放宽权限边界。

任何新 Agent 能力必须说明用户价值、授权方式、失败时的用户体验、可撤销性和评测方法；不能只因为模型“能调用”就加入生产能力。存储、队列、模型适配与互操作性等实现决策见[Agent 对话运行时技术设计](../tech/408-agent-conversation-runtime-design.md#15-未决项)；工作流框架、持久执行和任务执行库的比较、PoC 与 ADR 见[Agent 工作流技术选型与风险分析](../tech/408-agent-workflow-technology-selection-and-risk-analysis.md)。

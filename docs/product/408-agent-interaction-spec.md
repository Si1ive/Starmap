# 408 学习 Agent 交互规格

> 版本：v0.1
> 日期：2026-07-15
> 状态：高保真设计输入，不是最终视觉稿

## 1. 目的

本文把产品文字原型继续收敛为可直接绘制和评审的交互规格，重点回答：

- 每个页面第一视口放什么。
- 同一页面在空、慢、错、审批和恢复状态下如何变化。
- Agent 对话、工具运行、引用和结构化产物如何共存。
- 长题干、公式、图片和移动端如何保持可用。

视觉设计可以调整尺寸、色彩和动效，但不得改变本文定义的任务层级、状态语义和可信边界。

## 2. 本阶段产品决策

| 事项 | 决策 |
|------|------|
| 首批用户 | 单人自用和邀请制内测为主，但所有数据从第一天归属真实 `user_id` |
| 首发主线 | “提问到验证”是第一主线，“今日计划”提供可用基础版 |
| 主观题批改 | 按评分点反馈、指出缺失与错误，不承诺等同人工阅卷 |
| 工作名称 | 设计阶段统一使用“408 Agent”，品牌名在视觉设计阶段再定 |
| 客户端 | 响应式 Web；首发不做 PWA、桌面安装包或浏览器扩展 |
| 高风险能力 | 首发不提供通用 Shell、自由多 Agent 协作或无审批长期写入 |

## 3. 路由和可恢复状态

关键上下文必须进入 URL 或服务端状态，不能只保存在组件内存中。

```text
/onboarding
/today
/agent
/agent/{thread_id}?run={run_id}&artifact={artifact_id}
/map?subject={subject_id}&chapter={chapter_id}&point={point_id}
/practice/{session_id}?question={position}
/mistakes?status={status}&reason={reason}&point={point_id}
/sources?type={type}&source={source_id}
```

规则：

- 浏览器前进、后退后，当前线程、题目和筛选条件不丢失。
- 刷新运行中的 Agent 页面时，先读取服务端 run 快照，再续订事件。
- 练习当前题、已保存答案、标记状态和计时以服务端会话为事实源。
- 移动端进入引用、步骤或审批详情后，返回时恢复原滚动位置。

## 4. 应用壳

### 4.1 桌面

建议以 `1440 x 960` 为主设计画板，同时验证 `1280 x 800`：

- 左侧导航：稳定区域，包含一级导航、最近线程和账户。
- 中央工作区：唯一主要滚动容器，承载当前任务。
- 右侧上下文栏：引用、目标、步骤、审批或笔记，允许折叠。
- 全局任务中心：从顶栏状态入口打开，不使用遮挡主任务的常驻浮层。

中央工作区不能因右栏展开而低于可读宽度。空间不足时优先把右栏改成抽屉。

### 4.2 移动端

以 `390 x 844` 为主设计画板：

- 一级导航使用底部导航，只保留今日、Agent、练习、错题。
- 学习地图和资料放入“更多”。
- 右侧上下文栏改为底部抽屉或全屏次级页。
- 做题页隐藏全局导航，保留退出、进度和题目标记。
- 输入框不得遮挡最新消息、提交按钮或审批操作。

### 4.3 全局命令输入

输入区支持：

- 普通文本。
- 粘贴题目或图片。
- 引用当前考点、题目、错题或资料。
- 选择推荐动作，但不要求用户先选择“Agent 模式”才能发问。

发送后立即创建持久 run。按钮状态由 run 状态驱动，不用本地 `loading` 代表任务事实。

## 6. 今日

### 6.1 信息层级

第一视口从上到下：

1. 日期、目标阶段和今日可用时间。
2. 一个明确的“现在开始”主任务。
3. 今日任务队列。
4. 上次未完成任务和到期错题。
5. 本周进展，只展示与下一动作有关的趋势。

主任务必须说明推荐原因，例如：

> 昨天“循环队列下标计算”验证题答错，今天先复习 8 分钟，再做 2 道变式题。

不能只写“AI 为你推荐”。

### 6.2 状态矩阵

| 状态 | 页面表现 | 主动作 |
|------|----------|--------|
| 首次进入 | 无统计图，解释建立计划需要的最少信息 | 开始 10 分钟诊断 |
| 有计划 | 主任务突出，其他任务可扫描 | 开始任务 |
| 有未完成练习 | 主任务优先恢复真实进度 | 继续第 3/8 题 |
| Agent 正在重排 | 原任务仍可见，显示只读预览骨架 | 查看进度/取消 |
| 待确认重排 | 旧计划与新计划差异并列 | 应用调整/保留原计划 |
| 今日已完成 | 展示完成摘要和下一次到期复习 | 简短复盘 |
| 加载失败 | 保留最近成功快照并标记时间 | 重试 |

### 6.3 任务行

每行包含：

- 类型图标与任务名。
- 关联学科/考点。
- 预计时长。
- 推荐原因。
- 状态：未开始、进行中、待复习、完成、跳过。
- 主操作只出现一个，其余进入菜单。

任务行不是独立大卡片堆叠；应形成紧凑、可扫描的队列。

## 7. Agent 工作区

### 7.1 中央时间线节点

时间线允许以下节点交替出现：

| 节点 | 内容 |
|------|------|
| 用户消息 | 问题、附件和显式引用 |
| Agent 回答 | 结论、讲解和下一步建议 |
| 运行摘要 | “正在检索大纲与 6 道相关题” |
| 工具步骤 | 工具名、状态、耗时、影响和重试 |
| 引用组 | 关键结论对应的来源入口 |
| 结构化产物 | 练习集、计划、知识卡、错因报告 |
| 审批请求 | 将要执行的持续性动作和差异预览 |
| 错误节点 | 失败步骤、已保留结果和恢复动作 |

工具步骤默认收起，不显示隐藏思维链。用户展开后看到的是输入范围、结果摘要、耗时和错误，不是模型私有推理。

### 7.2 Run 状态矩阵

| Run 状态 | 输入区 | 时间线 | 全局任务中心 |
|----------|--------|--------|--------------|
| `queued` | 可继续输入，提示已排队 | 新增排队节点 | 显示排队 |
| `planning` | 可取消 | 显示正在组织步骤 | 显示规划中 |
| `running` | 可发补充消息，作为后续输入 | 当前步骤动态更新 | 显示进度 |
| `waiting_for_user` | 聚焦回答控件 | 显示明确问题 | 显示等待用户 |
| `waiting_for_approval` | 普通发送可用，审批按钮固定可见 | 显示差异和影响 | 显示待审批 |
| `completed` | 推荐下一动作 | 结果和产物完整 | 自动移入最近完成 |
| `failed` | 可继续新消息 | 保留成功步骤，标出失败步骤 | 显示可重试 |
| `cancelled` | 正常可用 | 显示取消位置和已产物 | 不再显示运行中 |

### 7.3 回答结构

408 讲解默认采用：

1. 直接回答当前问题。
2. 核心规则或解法。
3. 易错点。
4. 引用证据。
5. 一个明确下一步，例如“用 2 道题验证”。

短问题不强制生成长篇章节。长回答支持目录定位，但不要把每个小段都做成卡片。

### 7.4 引用

正文关键结论后使用紧凑引用标记。点击后右栏定位到具体证据：

- 来源等级。
- 文档/试卷名称。
- 页码或题号。
- 支撑该结论的片段。
- 平台审核状态。
- 打开原始页或原题。

来源不足时显示“模型推断”，不能伪造页码或用无关引用装饰答案。

### 7.5 审批

审批节点必须回答：

- Agent 要做什么。
- 为什么需要做。
- 哪些数据会改变。
- 是否可撤销。
- 拒绝后当前任务是否还能继续。

计划调整使用差异视图，不只显示“是否允许修改计划”。

## 8. 学习地图

### 8.1 总览

首发使用可展开的大纲树和进度列表，不做 3D 图谱。四门学科是稳定一级分组，节点显示：

- 学习状态。
- 最近正确率与样本数。
- 待复习数。
- 重要程度。
- 最近一次学习时间。

没有足够证据时显示“证据不足”，不显示伪精确百分比。

### 8.2 考点详情

信息顺序：

1. 考点名、所属大纲路径和当前状态。
2. 一句话定义与核心内容。
3. 掌握证据。
4. 前置、易混和关联考点。
5. 对应真题、练习和个人错题。
6. 来源与个人笔记。

固定动作：

- 请 Agent 讲解。
- 开始专项练习。
- 查看我的错误。

## 9. 练习工作区

### 9.1 作答前

- 顶部固定：退出、题号进度、剩余时间（如有）、标记不确定。
- 正文区：题干、公式、图片或表格。
- 答题区：根据题型使用单选、多选、判断、文本或结构化输入。
- 底部操作：上一题、暂存/下一题、提交。

来源、难度等次要信息不应压过题干。

### 9.2 客观题提交后

立即显示：

- 对错与正确答案。
- 用户答案。
- 最关键的一条错误说明。
- 是否使用提示、用时是否异常。

深度内容按需展开：

- 完整解析。
- 关联考点。
- 逐项选项分析。
- 原题来源。
- 下一道变式题。

### 9.3 主观题提交后

反馈不是一个不透明总分，先展示评分点：

| 评分点 | 状态 | 证据 |
|--------|------|------|
| 写出基本设计思想 | 满足/部分/缺失 | 对应用户答案片段 |
| 算法描述正确 | 满足/部分/缺失 | 关键步骤差异 |
| 时间复杂度 | 满足/部分/缺失 | 标准要求与用户结论 |

必须标明“AI 辅助反馈”，允许用户对评分点提出异议。正式成绩预测不进入首发。

### 9.4 题目来源

| 来源 | 标签 | 行为 |
|------|------|------|
| 原始真题/试卷 | 原题 | 可查看试卷、题号和页码 |
| 已审核平台题 | 平台题 | 可查看审核与出处 |
| 平台改编 | 改编题 | 说明改编自何考点 |
| AI 临时生成 | AI 生成 | 明确标记，不混入原题统计 |
| 原文恢复选项 | 原文恢复 | 只在来源详情显示修复记录 |
| AI 补充选项 | AI 补充 | 在题目来源处可见并降低信任等级 |

## 10. 错题与复盘

默认先显示“需要处理的错因簇”，再显示题目列表。

错因簇包含：

- 错因名称和一句可执行描述。
- 关联考点。
- 最近 30 天次数。
- 代表题。
- 已学习、待验证、已解决状态。
- 建议动作。

“已解决”要求在合理间隔后通过新题验证。查看答案、收藏或手动关闭不能自动提高掌握状态。

## 11. 资料

首发状态：

| 状态 | 表现 |
|------|------|
| 等待上传 | 清晰上传入口和支持格式 |
| 上传中 | 文件级进度，可取消 |
| 解析中 | 服务端真实阶段，可离开页面 |
| 可使用 | 页数、类型、最近引用和删除入口 |
| 部分成功 | 可用页与失败页分开说明 |
| 失败 | 失败阶段、原因和重试 |
| 删除中 | 禁止重复删除，说明索引清理状态 |

平台资料与个人资料在列表、检索筛选和引用样式上保持可区分，但不使用刺眼的警示色制造噪声。

## 12. 共用组件状态

| 组件 | 必须状态 |
|------|----------|
| 命令输入 | 默认、聚焦、含引用、上传中、发送失败、禁用 |
| 任务状态入口 | 无任务、运行中、待审批、失败、最近完成 |
| Agent 步骤 | 等待、运行、成功、失败、跳过、取消 |
| 引用标记 | 平台、原题、个人资料、模型推断、不可用 |
| 练习选项 | 默认、悬停、选中、正确、错误、禁用 |
| 题目标记 | 未标记、不确定、稍后检查 |
| 掌握状态 | 未学习、证据不足、学习中、待巩固、已掌握 |
| 审批面板 | 待决定、已同意、已拒绝、已过期、执行失败 |
| Toast | 只反馈轻量瞬时结果；重要失败必须留在页面 |

## 13. 内容压力测试

每个高保真页面必须用真实或等价复杂度内容验证：

- 600 字以上题干。
- 四个均超过两行的选项。
- 公式与中英文混排。
- 一道带两张图的主观题。
- 一条含 5 个引用的回答。
- 一个含 8 个步骤、其中 1 个失败的 Agent run。
- 20 个字符以上的考点名和三级大纲路径。
- 移动端软键盘展开后的输入、提交和审批。

不得通过缩小到不可读字号解决溢出，也不能让状态标签覆盖题干、考点或抽取质量信息。

## 14. 交互与可访问性

- 所有图标按钮有可见悬停提示和无障碍名称。
- 键盘可以完成发送、选择答案、下一题、打开引用和处理审批。
- 颜色不是对错、状态和来源的唯一表达。
- 运行进度更新不抢夺输入焦点。
- 动效用于解释状态变化，不做连续装饰。
- 题目、答案和引用支持文本选择。
- 用户离开未提交主观题前必须提示，已自动保存则明确最后保存时间。

## 15. 高保真评审门禁

进入实现前必须同时满足：

1. P01-P20 均有对应画面或明确复用关系。
2. “提问到验证”可从头点击到尾，不依赖口头解释。
3. 运行中切页、刷新恢复、失败重试和待审批均有设计。
4. 原题、平台内容、个人资料和模型生成内容可区分。
5. 选择题、长主观题、公式和图片题均验证通过。
6. 桌面与移动端都没有内容重叠、截断或关键操作不可达。
7. 页面第一视口是实际任务，不是产品宣传。

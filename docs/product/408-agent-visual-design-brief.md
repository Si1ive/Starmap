# 408 Agent 高保真设计执行简报

> 版本：v0.1
> 日期：2026-07-15
> 状态：等待设计 Skill 执行
> 输出目标：可运行、可点击、使用真实 408 内容的桌面与移动端高保真原型

## 1. 设计任务

设计的不是一个 AI 聊天页面，也不是知识库、刷题和仪表盘的拼接，而是一个持续工作的
408 学习工作台。

高保真原型必须让用户在不听讲解的情况下看懂并完成以下主线：

```text
提出问题
  -> 观察 Agent 检索和组织过程
  -> 核验讲解来源
  -> 进入验证题
  -> 提交答案
  -> 确认错因
  -> 形成后续复习任务
```

原型用于拍板真实产品，不是营销展示稿。第一屏必须是可执行任务，不制作宣传首页。

## 2. 推荐视觉方向

### 2.1 方向名称

**专注型学术工作台**

关键词：

- 冷静。
- 清晰。
- 可信。
- 高信息密度但不拥挤。
- 长时间学习不疲劳。
- 像成熟的学习工具，不像“AI 炫技页面”。

产品应同时具有两种气质：

1. 试卷、教材和学习记录带来的严谨感。
2. Agent 持续执行、可恢复和可核验带来的现代工具感。

### 2.2 第一视觉信号

用户进入页面后，第一眼应看到：

- 今天最应该完成的动作；或
- 当前 Agent 线程正在解决的问题；或
- 当前正在作答的题目。

产品名、导航和统计只能辅助任务，不能比任务本身更强。

### 2.3 色彩意图

以浅色界面为第一版，不做深色优先。

| 角色 | 建议方向 | 用途 |
|------|----------|------|
| 页面底色 | 低饱和冷灰白 | 降低长时间阅读疲劳 |
| 主表面 | 白色或接近白色 | 题目、时间线和编辑区域 |
| 主文字 | 接近黑色的中性墨色 | 正文、题干和结论 |
| 次文字 | 中性灰绿 | 元数据、说明和时间 |
| 主操作 | 清晰的钴蓝 | 发送、开始、提交等明确动作 |
| 学习进展 | 稳定的青绿色 | 完成、掌握证据和可恢复成功 |
| 待审批 | 克制的琥珀色 | 需要用户判断的持续性动作 |
| 错误 | 低饱和红色 | 失败、错误答案和破坏性操作 |

要求：

- 不使用紫蓝渐变作为产品主视觉。
- 不使用装饰性光斑、圆球、玻璃拟态或大面积渐变。
- 来源、状态和对错不能只靠颜色表达，必须同时使用文字或图标。
- 不把整个界面做成单一蓝色或单一灰色体系。

设计 Skill 可以微调具体色值，但不得改变上述语义分工。

### 2.4 字体与排版

- 中文正文优先使用清晰的无衬线字体，兼容 `PingFang SC`、`Noto Sans SC`
  和系统字体。
- 数字、英文缩写和运行时间可以使用与中文协调的西文字体。
- 公式统一使用 KaTeX 或等价数学排版，不把公式当普通斜体文本。
- 工作区页面标题建议控制在 24-28px，紧凑面板标题使用 16-20px。
- 正文建议 15-16px；元数据不得小到影响连续阅读。
- 字号不随视口宽度缩放，字距为 0。
- 长题目采用稳定行宽，不让正文横跨整个宽屏。

## 3. 布局系统

### 3.1 桌面基准

主画板：`1440 x 960`。

必须额外验证：`1280 x 800`。

建议布局：

```text
┌──────────┬──────────────────────────┬──────────────┐
│ 左侧导航 │       中央任务区         │ 右侧上下文栏 │
│ 220-248  │       680-860            │ 288-336      │
└──────────┴──────────────────────────┴──────────────┘
```

规则：

- 中央任务区是唯一主要视觉焦点。
- 右栏展开后，中央正文仍需保持可读宽度。
- `1280px` 下空间不足时，右栏切换为抽屉，不压缩题目和回答。
- 页面区段使用连续布局，不把每个区段都包成漂浮卡片。
- 卡片仅用于独立产物、审批、重复题目项或确实需要边界的工具。
- 卡片圆角不超过 8px，不允许卡片嵌套卡片。
- 阴影只用于抽屉、弹层或悬浮层级，不用于所有内容块。

### 3.2 移动基准

主画板：`390 x 844`。

规则：

- 底部导航保留今日、Agent、练习、错题。
- 学习地图和资料进入“更多”。
- 做题时进入专注模式，隐藏底部全局导航。
- 引用、步骤和审批使用底部抽屉或全屏次级页。
- 软键盘展开后，输入框、最新消息和主操作仍可到达。
- 从上下文抽屉返回时恢复中央内容滚动位置。

### 3.3 稳定尺寸

以下控件必须定义稳定尺寸，动态内容不得使布局跳动：

- 导航图标与行高。
- Agent 步骤状态图标。
- 题号导航。
- 选择题选项标记。
- 来源标记。
- 主按钮和图标按钮。
- 任务进度与计时区域。
- 移动端底部操作区。

## 4. 组件视觉语法

### 4.1 导航

- 使用 Lucide 图标或实现时采用的统一图标库。
- 图标按钮必须有悬停提示和无障碍名称。
- 最近线程是紧凑列表，不做多张会话卡片。
- 当前导航使用位置、字重和克制底色共同表达，不只改变文字颜色。

### 4.2 今日任务队列

- 一个明确的主任务可以获得较强层级。
- 其余任务使用紧凑行，不使用同尺寸大卡片堆叠。
- 每行只保留一个主操作，其余动作进入菜单。
- 推荐原因必须与任务同屏可见，不能隐藏在“AI 推荐”提示中。

### 4.3 Agent 时间线

- 用户消息、Agent 回答、工具步骤和结构化产物具有不同结构。
- 不把所有节点渲染成左右聊天气泡。
- Agent 正文优先使用文档式排版。
- 工具步骤默认收起，用状态、名称、耗时和结果摘要形成连续执行轨迹。
- 运行中只更新对应步骤，不让整个页面反复闪烁或位移。
- 错误节点保留已经完成的步骤和产物。

### 4.4 引用

- 正文引用标记要容易发现，但不能像广告标签一样打断阅读。
- 右栏证据详情包含来源等级、文档或试卷、页码或题号、支撑片段和审核状态。
- “模型推断”必须与平台证据采用不同图标和文字。
- 多个来源使用列表，不把每条来源做成大卡片。

### 4.5 练习

- 题干和题图拥有最高内容层级。
- 选项使用稳定的 A-D 标记与整行点击区域。
- 选中、正确、错误和禁用状态不能改变选项整体尺寸。
- 题目来源和难度放在次要位置，不覆盖题干。
- 客观题提交后先显示关键反馈，再按需展开完整解析。
- 主观题按小问保存草稿，反馈按评分点组织。

### 4.6 审批

- 待审批动作使用差异视图，不只显示确认弹窗。
- 清楚区分将删除、将新增和保持不变的内容。
- 同意和拒绝按钮距离充足，拒绝不是危险红色操作。
- 可撤销状态和影响范围必须同屏展示。

### 4.7 状态反馈

- Toast 只用于轻量瞬时反馈。
- Agent 失败、资料解析失败和提交失败必须留在对应工作区。
- Skeleton 只表示尚未获得数据，不伪装成 Agent 正在执行。
- 运行状态由服务端 run 驱动，不使用按钮本地 loading 充当任务事实。

## 5. 可点击原型脚本

设计 Skill 至少实现以下五条可点击路径。每一步都必须能通过画面上的真实操作进入下一步。

### D1：提问到验证

使用样例：`FT-01`、`FQ-01`。

```text
P07 Agent 新线程
  -> 输入循环队列问题
P08 检索与讲解运行中
  -> 展开一个工具步骤
  -> 等待结果
P09 讲解完成
  -> 打开原题引用
P20 引用详情
  -> 返回线程
  -> 点击“用 2 道题验证”
P14 选择题作答
  -> 选择 B 并提交
P16 客观题反馈
  -> 确认“少考虑包含队尾本身”
P18 错题与复习
  -> 查看已创建的下次复习任务
P04 今日
  -> 看到该任务进入队列
```

验收重点：

- 用户能区分回答、工具过程、引用和验证题。
- 练习不是跳到一个与原线程无关的孤立页面。
- 错因和复习任务形成闭环。

### D2：运行恢复与局部重试

使用样例：`FT-02`。

```text
P08 Agent 运行中
  -> 打开全局任务中心
  -> 切换到 P12 学习地图
  -> 从任务中心返回原线程
P10 失败恢复
  -> 查看已保留的 3 道题练习草稿
  -> 点击“仅重试失败步骤”
P08 失败步骤重新运行
  -> 完成后回到 P09
```

需要在原型注释中说明刷新恢复使用同一 `run_id`，不创建重复练习。

### D3：长主观题与图片反馈

使用样例：`FQ-03`。

```text
P15 长主观题
  -> 打开处理机图
  -> 全屏缩放
  -> 返回并填写第 1 小问
  -> 看到自动保存时间
  -> 提交
P17 评分点反馈
  -> 展开“寄存器位数”评分点
  -> 查看用户答案片段和参考要求
```

桌面与移动端都必须使用真实两张题图，不得使用灰色占位框。

### D4：计划调整审批

使用样例：`FT-03`。

```text
P11 待审批
  -> 查看旧计划与新计划差异
  -> 选择拒绝，验证原计划不变
  -> 返回再次打开审批
  -> 选择同意
P06 计划应用预览
  -> 确认版本和撤销入口
P04 今日
  -> 查看更新后的任务
```

### D5：移动端核心闭环

使用 `390 x 844` 画板完成：

```text
P04 今日
  -> P07 新线程
  -> P08 运行中
  -> 底部抽屉查看步骤
  -> P09 讲解完成
  -> 全屏查看引用
  -> P14 作答
  -> P16 反馈
```

必须验证软键盘展开、长公式、两行以上按钮文案和底部安全区。

## 8. 设计 Skill 可调整范围

可以调整：

- 工作名称的字标形式。
- 具体色值与字体组合。
- 图标笔画风格。
- 左右栏的精确尺寸。
- 符合状态语义的微动效。
- 在不改变任务层级前提下的局部信息排序。

必须保持：

- Web-first。
- “提问到验证”第一主线。
- 今日、Agent、学习地图、练习、错题、资料六个一级入口。
- Agent 运行由服务端状态驱动的交互表现。
- 原题、平台内容、个人资料、AI 生成和模型推断可区分。
- 长期修改需要审批或可撤销。
- 主观题只提供评分点辅助反馈。
- 长题干、公式、图片和移动端完整可用。

## 9. 禁止方向

- 营销型 Hero 或产品介绍首页。
- 以聊天气泡占满整个产品。
- 紫色霓虹、AI 光效、装饰性渐变和漂浮圆球。
- 大量同尺寸统计卡片。
- 卡片嵌套卡片。
- 用一排彩色标签替代信息层级。
- 只设计成功态，不设计运行、失败、恢复和审批。
- 用缩小字体处理长题干。
- 把内部 MinerU、数据库字段或质量门禁术语展示给学习用户。
- 复制当前管理端的视觉结构。

## 11. 高保真最终门禁

在用户确认并进入正式实现前，必须证明：

1. P01-P20 均存在，不靠口头补充缺失状态。
2. D1-D5 可以从画面真实点击走通。
3. FQ-01、FQ-02、FQ-03 在桌面和移动端无重叠、截断或错误题型。
4. Agent 切页、刷新、失败和局部重试的状态不会看似消失。
5. 来源不足时明确降级，不伪造证据。
6. 审批前不表现为已经修改长期计划。
7. 页面第一视口始终是学习任务，不是宣传、空统计或 AI 装饰。
8. 原型不依赖后端即可稳定演示，后续实现时再映射正式 API。

# 408 学习 Agent 文字原型

> 版本：v0.1
> 日期：2026-07-15
> 状态：待产品方向对齐，视觉设计尚未开始

## 1. 决策摘要

产品不再按“首页、知识库、刷题、聊天”四个孤立功能建设，而是做成一个持续工作的 **408 学习工作台**。

用户每天打开产品后，首先看到自己当前最需要完成的学习动作。Agent 可以基于考试日期、目标分数、知识掌握度、最近错题和当前对话上下文，组织学习计划、讲解、练习、批改和复盘。知识库与题库不再只是独立入口，而是 Agent 可调用且用户可核验的内容基础设施。

一句话定位：

> 一个能理解 408 大纲、知识库、题库和个人学习状态，并陪用户完成“诊断、学习、练习、批改、复盘”闭环的学习 Agent。

## 2. 产品边界

### 2.1 第一阶段必须解决

- 用户不知道今天应该学什么。
- 用户遇到知识盲点时，只得到一次性答案，没有后续巩固。
- 刷题、知识点、错题和对话彼此割裂。
- 普通聊天产品不了解 408 大纲、考频、题型和用户历史错误。
- 用户难以判断 Agent 回答来自教材、原题还是模型生成。

### 2.2 第一阶段不解决

- 通用办公 Agent。
- 任意网站或桌面软件自动操作。
- 完整笔记软件和网盘替代品。
- 全功能课程平台、直播和社交社区。
- 无审批的系统命令执行。
- 为了“像桌面软件”而提前建设安装、更新和跨平台发布体系。

## 3. 目标用户与核心任务

### 3.1 首要用户

正在准备计算机考研 408、已经开始系统复习，但需要更高效地定位薄弱点和组织练习的学生。

### 3.2 核心用户任务

1. “根据我的目标和当前水平，告诉我今天最该完成什么。”
2. “把这个知识点讲到我真正理解，并马上出题验证。”
3. “分析我为什么错，不要只告诉我正确答案。”
4. “从大纲、教材和真题证据出发回答，并让我能追溯来源。”
5. “把最近的错误归纳成可执行的复习任务。”
6. “按目标章节、题型和难度组织一次练习或模拟。”
7. “我上传自己的资料后，结合平台知识库帮我学习。”

## 4. 产品原则

### 4.1 行动优先于聊天

对话是交互方式，不是产品结构。Agent 的有效输出应尽量落成可执行对象，例如今日任务、练习集、错因诊断、知识卡片或复盘报告。

### 4.2 每次学习形成闭环

标准闭环：

`目标 -> 诊断 -> 学习 -> 练习 -> 批改 -> 归因 -> 间隔复习`

任何讲解都应该能够进入练习，任何错误都应该能够回到知识点和后续计划。

### 4.3 知识来源可核验

- 平台知识库内容显示来源文档、页码和关联考点。
- 原题与 AI 生成题明确区分。
- Agent 推断与教材原文明确区分。
- 关键结论支持展开引用，不只显示一个笼统“知识库来源”标签。

### 4.4 Agent 行动可观察、可中断、可恢复

用户应看到 Agent 当前在检索、组题、批改还是更新计划。长任务可以离开页面，回来后继续显示真实状态和结果。

### 4.5 用户掌握最终控制权

修改长期计划、归档错题、导入本地资料、覆盖用户笔记等有持续影响的动作，需要明确预览或确认。只读检索、生成临时练习等低风险动作可以自动执行。

### 4.6 不奖励无效使用时长

产品成功指标不是聊天次数，而是完成的学习闭环、薄弱点改善和可解释的掌握度变化。

## 5. 核心领域对象

| 对象 | 作用 |
|------|------|
| 用户档案 | 考试日期、目标分数、每日时间、当前阶段、偏好 |
| 学习目标 | 长期目标、阶段目标、章节目标和截止时间 |
| 今日任务 | 可完成、可跳过、可调整顺序的学习动作 |
| Agent 线程 | 围绕一个目标持续存在的对话和工作上下文 |
| Agent 运行 | 一次可观察、可恢复的规划或工具执行过程 |
| 学习产物 | 计划、知识卡片、练习集、错因报告、复盘 |
| 练习会话 | 一组题及其作答、用时、提示和批改状态 |
| 错题记录 | 原题、用户答案、错因、关联考点和复习状态 |
| 掌握状态 | 用户在学科、章节和考点层面的证据化状态 |
| 用户资料 | 用户主动上传的 PDF、图片、笔记或题目 |
| 引用证据 | 平台文档、页码、题目、用户资料及检索分数 |
| 审批项 | Agent 准备执行、但需要用户确认的持续性动作 |

## 6. 信息架构

### 6.1 一级导航

| 入口 | 目的 |
|------|------|
| 今日 | 当前计划、待完成动作、最近进度和快捷开始 |
| Agent | 持久线程、任务运行和学习产物 |
| 学习地图 | 408 大纲、章节进度、掌握度和知识关系 |
| 练习 | 专项练习、智能组卷、模拟考试和历史记录 |
| 错题 | 错因聚类、待复习队列和再次验证 |
| 资料 | 平台来源、用户资料、笔记和引用管理 |

“设置”和“个人报告”放在账户菜单，不占一级学习导航。

### 6.2 全局入口

- 全局命令输入：随时向 Agent 发起问题或动作。
- 当前学习上下文：学科、章节、考点、题目或资料。
- 任务状态中心：显示运行中、待审批、失败和已完成的 Agent 任务。
- 快速继续：恢复上次未完成的练习或讲解。

## 7. 主工作台布局

桌面宽度下采用三栏工作区，而不是营销型首页：

### 7.1 左侧导航栏

- 产品标识。
- 一级导航。
- 最近 Agent 线程。
- 新建线程。
- 账户与同步状态。

左栏保持稳定，不展示大量统计卡片。

### 7.2 中央工作区

承载当前真正执行的任务：

- 今日任务队列。
- Agent 对话与工具运行。
- 知识讲解。
- 做题与批改。
- 学习产物编辑。

同一个线程内，聊天消息和结构化产物可以交替出现，但练习、计划等复杂内容应使用专门工作面板，不塞进对话气泡。

### 7.3 右侧上下文栏

根据当前任务动态切换：

- 当前目标和进度。
- 关联考点。
- 引用证据。
- Agent 执行步骤。
- 待审批动作。
- 笔记与收藏。

右栏可折叠。移动端以底部抽屉或独立页呈现，不强行压缩三栏。

## 8. 页面文字原型

### 8.1 首次使用与诊断

目标：用最短流程建立可用的个人学习上下文。

步骤：

1. 填写考试日期、目标分数、每天可用时间。
2. 选择当前复习阶段：未开始、基础、强化、冲刺。
3. 选择已学章节，可跳过。
4. 完成一组跨学科自适应诊断题。
5. 展示初始薄弱点和第一周建议计划。
6. 用户确认后生成“今日”任务。

诊断结果必须说明证据，例如“进程同步连续两题错误”“Cache 地址映射用时显著偏长”，避免输出空泛能力标签。

### 8.2 今日

第一视口直接展示：

- 距离考试天数和本周目标进度。
- 当前最推荐任务，带预计时长和推荐原因。
- 继续上次未完成任务。
- 今日剩余任务队列。
- 近期需要复习的错题。

推荐任务示例：

- 学习：虚拟内存页表，20 分钟。
- 练习：虚拟内存专项 8 题，15 分钟。
- 复盘：昨日错题 3 题，10 分钟。

用户可以开始、跳过、调整时长或让 Agent 重排当天计划。重排前显示影响，不静默修改长期目标。

### 8.3 Agent 工作区

线程创建时可以直接输入自然语言，也可以选择一个工作模式：

- 问懂一个知识点。
- 分析一道题。
- 生成学习计划。
- 组织专项练习。
- 复盘最近错误。
- 处理一份资料。

中央时间线包含：

- 用户消息。
- Agent 简短的行动说明。
- 工具执行状态。
- 可编辑的结构化产物。
- 结果摘要和下一步动作。

示例流程：

1. 用户：“我总是分不清中断、异常和系统调用。”
2. Agent 检索大纲、知识点、易混关系和相关题目。
3. 生成对比讲解，引用来源。
4. 用户点击“用题验证”。
5. Agent 组织 3 题递进练习。
6. 根据作答给出错因，并把未掌握项加入复习队列。

Agent 不应每次都输出冗长“思考过程”，只展示对用户有用的动作、证据和状态。

### 8.4 学习地图

默认按 408 大纲展示四门学科及章节树。

每个节点显示：

- 掌握状态：未学习、学习中、待巩固、已掌握。
- 掌握证据：最近正确率、作答次数、最近复习时间。
- 考频和重要程度。
- 待处理错题数。

选择考点后，中央区域显示：

- 核心讲解与关键结论。
- 前置和关联考点。
- 对应真题与练习。
- 个人错误和笔记。
- “请 Agent 讲解”“开始专项练习”等直接动作。

掌握度不是模型凭空给出的百分数，而是由作答、用时、提示使用、复习间隔等证据计算，并允许用户查看依据。

### 8.5 练习工作区

入口类型：

- Agent 推荐。
- 按章节练习。
- 按题型练习。
- 错题重练。
- 智能组卷。
- 完整模拟。

做题期间页面保持专注：

- 题干和必要图片是主要内容。
- 客观题使用适合题型的输入控件。
- 简答题支持文本、公式和草稿。
- 可标记不确定、稍后检查。
- 提示按层级逐步揭示，并计入掌握度证据。

提交后分两层反馈：

1. 立即反馈：结果、正确答案、关键错误。
2. 深度分析：考点、错因、解法路径、相关练习和复习安排。

原题、平台改编题和 AI 生成题必须有明确来源标记。AI 生成题在进入正式题库前不伪装成真题。

### 8.6 错题与复盘

错题列表不只按题目堆积，而按错因聚类：

- 概念混淆。
- 条件遗漏。
- 计算错误。
- 解题策略不熟。
- 审题错误。
- 知识未覆盖。

每个错因簇展示：

- 涉及考点。
- 代表题目。
- 最近发生次数。
- 是否已通过后续题目验证。
- 建议复习动作。

错题只有在用户完成间隔后的再次验证后，才进入“已解决”，不能仅因看过解析就自动消失。

### 8.7 资料

第一阶段：

- 上传 PDF、图片和文本笔记。
- 查看解析状态。
- 在 Agent 线程中引用资料。
- 区分平台权威知识库与个人资料。

后续本地能力：

- 授权一个本地资料目录。
- 监听新增或修改的文件。
- 只同步索引或用户明确选择的内容。
- 显示每个目录的权限、同步范围和最近活动。

本地目录访问不是第一版的前置条件。

### 8.8 个人报告

报告回答四个问题：

1. 最近完成了什么。
2. 哪些知识正在改善。
3. 哪些错误反复出现。
4. 下一阶段最值得投入什么。

报告优先展示趋势和证据，不使用无法解释的综合分数。

## 9. Agent 模式与工具

### 9.1 用户可感知模式

| 模式 | 行为 |
|------|------|
| 讲解 | 检索知识证据，分层解释并验证理解 |
| 解题 | 分析题目条件、考点和解法；默认不提前泄露答案 |
| 练习 | 选题或生成题目、控制难度、记录作答 |
| 批改 | 客观题判定，主观题按评分点给出证据化反馈 |
| 规划 | 结合目标、可用时间和掌握状态生成任务 |
| 复盘 | 聚合近期行为和错因，安排再次验证 |
| 资料 | 解析用户资料并与平台知识关联 |

### 9.2 Agent 内部工具

- 检索大纲、章节、知识点和关系。
- 检索真题与练习题。
- 获取用户掌握状态和历史作答。
- 创建练习会话。
- 提交并批改答案。
- 创建或调整学习计划。
- 创建复习任务。
- 生成学习产物。
- 检索用户资料。
- 请求用户审批。

工具调用必须返回结构化结果，不能依赖 Agent 从自然语言中猜测执行是否成功。

## 10. 三条首发核心工作流

### 10.1 问题到掌握

`提问 -> 检索证据 -> 分层讲解 -> 生成验证题 -> 作答 -> 错因 -> 加入复习`

这是产品区别于普通 RAG 聊天的最小闭环。

### 10.2 错题到复习

`提交错误答案 -> 定位考点 -> 识别错因 -> 推荐材料 -> 延迟重测 -> 验证解决`

这是个性化能力的主要数据来源。

### 10.3 目标到今日任务

`目标与时间 -> 初始诊断 -> 周计划 -> 今日任务 -> 执行记录 -> 动态重排`

这是用户持续返回产品的主入口。

## 11. 可信与审批设计

### 11.1 来源等级

1. 原始试卷或官方大纲。
2. 已审核的平台知识点和题目。
3. 用户资料。
4. Agent 推断或生成内容。

界面显示来源类型，不用统一的“AI 生成”掩盖差异。

### 11.2 必须审批的动作

- 修改长期或周学习计划。
- 删除学习记录、错题或用户资料。
- 持久化 Agent 生成的个人笔记。
- 授权本地目录或浏览器上下文。
- 向外部服务发送用户资料。

### 11.3 可自动执行的动作

- 只读检索。
- 生成临时讲解。
- 组织临时练习。
- 保存当前线程消息。
- 更新当前 Agent 运行进度。

## 12. 空、错、慢状态

### 12.1 无学习记录

引导完成诊断或从一个章节开始，不展示没有意义的空统计图。

### 12.2 无可靠检索结果

Agent 明确说明证据不足，可以提出澄清问题或只给出标记为“模型推断”的回答。

### 12.3 长任务

显示阶段、已完成步骤、可取消操作和预计下一结果。用户切页或关闭浏览器后，运行状态仍可恢复。

### 12.4 工具失败

显示失败工具、影响范围和可重试动作。已经完成的步骤不重复执行，避免重复创建练习或计划。

## 13. 首发范围

首发只实现能够形成闭环的六个界面：

1. 首次诊断。
2. 今日。
3. Agent 工作区。
4. 学习地图。
5. 练习工作区。
6. 错题与复盘。

资料页第一版仅支持主动上传。报告页可在积累足够学习数据后再开放。

## 14. 设计 Skill 接入后的工作

后续视觉设计应基于本文档，而不是重新发明产品结构：

- 确定品牌名、字体、颜色和图标语言。
- 输出桌面与移动端导航方案。
- 为今日、Agent、练习三条主流程制作高保真原型。
- 定义 Agent 运行、引用、审批和错误状态组件。
- 验证长题干、公式、图片、引用和多步骤任务下的布局稳定性。
- 使用真实 408 题目和知识点数据制作原型，不使用占位营销文案。

## 15. 待对齐项

以下事项不阻塞技术准备，但应在高保真设计前拍板：

1. 首批用户是否以“单人自用”验证为主，还是首发即支持公开注册。
2. 第一版是否把学习计划作为强主线，还是先以“提问到练习”闭环为主线。
3. 产品最终名称和视觉气质。
4. 主观题批改是否进入首发范围。

本文档建议：

- 先按单人自用的数据模型开发，但从第一天使用真实 `user_id` 隔离数据。
- 首发主线是“提问到练习”，今日计划作为第二条闭环同时保留基础版本。
- 主观题批改先支持评分点反馈，不承诺与人工阅卷完全等价。

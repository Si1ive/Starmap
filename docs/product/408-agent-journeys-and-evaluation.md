# 408 学习 Agent 用户旅程与评测脚本

> 版本：v0.1
> 日期：2026-07-15
> 用途：高保真原型验收、可用性测试、Agent 离线评测与开发验收

## 1. 核心验收原则

产品不是以“Agent 回答了一段话”为完成，而以用户是否完成一个可追踪学习闭环为完成。

每条旅程同时验证：

- 用户能否理解下一步。
- Agent 状态能否恢复。
- 知识来源是否可信。
- 学习行为是否形成持久记录。
- 失败后是否保留已经成功的结果。

## 2. 旅程 J1：提问到验证

### 场景

用户不理解循环队列队首位置公式，希望理解而不是死记。

### 前置

- 用户已有真实身份。
- 平台存在循环队列大纲节点、知识内容和 FQ-01。
- 用户同类题最近有错误记录。

### 步骤

1. 用户在 Agent 输入自然语言问题。
2. 页面立即创建 run 并显示正在检索的对象范围。
3. Agent 返回简短结论、推导、易错点和引用。
4. 用户打开一条引用，能定位到大纲或原题证据。
5. 用户点击“用 2 道题验证”。
6. 页面进入内嵌练习，用户第一题选择 B。
7. 提交后显示正确答案 C 和主错因候选。
8. 用户确认自己的错因。
9. 系统创建后续复习任务，并说明何时再次验证。

### 成功标准

- 用户不需要离开线程寻找练习。
- 回答至少有一条直接支撑核心规则的可靠来源。
- 作答、错因和复习任务均归属同一用户。
- 回到线程后可看到练习结果和后续任务。

### 禁止行为

- 在用户点击验证前直接显示验证题答案。
- 用低质量 FQ-05/FQ-06 为凑题数。
- 未经确认把一次错误解释成稳定人格或能力结论。
- 把 AI 生成题标成原题。

## 3. 旅程 J2：切页和刷新后恢复运行

### 场景

用户让 Agent 创建一个 20 题专项练习，运行约需一分钟。用户切到学习地图后再返回，并刷新页面。

### 步骤

1. 创建 run，状态从 `queued` 进入 `running`。
2. Agent 已完成检索与候选题过滤，正在生成提示。
3. 用户切到学习地图。
4. 全局任务中心继续显示真实状态。
5. 用户返回原线程并刷新。
6. 客户端读取 run 快照，从最后事件序号续订。
7. 任务完成，页面只出现一个练习产物。

### 成功标准

- 切页不会让按钮恢复成“未开始”。
- 刷新后不重复运行已完成工具。
- 服务端完成时，即使当前页未打开，也能在任务中心看到结果。
- 同一幂等键只产生一个练习会话。

## 4. 旅程 J3：工具成功、LLM 超时

### 场景

Agent 已经创建 3 道题的练习草稿，但生成逐题提示时模型超时。

### 步骤

1. 页面显示前 3 个步骤成功。
2. 失败节点说明“提示生成失败”，而不是笼统“任务失败”。
3. 用户可选择“仅重试失败步骤”。
4. 用户也可直接开始无提示练习。
5. 重试成功后更新原产物，不创建重复练习。

### 成功标准

- 已创建练习不会消失。
- 重试范围和影响可理解。
- 用户不需要重新输入原请求。

## 5. 旅程 J4：长主观题与图片

### 场景

用户完成 FQ-03 处理机数据通路题。

### 步骤

1. 进入题目后先看到完整题干和两张清晰题图。
2. 点击图片可无损放大，并可在题目和答案间返回。
3. 用户按小问保存答案草稿。
4. 提交后按寄存器位数、取指步骤和执行步骤显示评分点。
5. 每个评分点引用用户答案片段和参考要求。
6. 页面明确标注“AI 辅助反馈”，允许用户提出异议。

### 成功标准

- 图片不被裁掉关键标号。
- 长题干和答题区不相互遮挡。
- 自动保存时间可见。
- 不把评分总分作为唯一反馈。

## 6. 旅程 J5：主观题 A/B/C/D 不被误判为选项

### 场景

用户打开 FQ-02，其中 A、B、C、D 是寄存器名。

### 成功标准

- 页面使用主观题输入区，不显示选择控件。
- Agent 不生成所谓“缺失 D 选项”。
- 讲解和评分按三个小问组织。
- 来源详情可以说明题型为简答题，但不暴露内部解析修复日志。

## 7. 旅程 J6：计划调整审批

### 场景

Agent 根据连续错题建议把周四 20 分钟排序练习替换为死锁复习。

### 步骤

1. Agent 展示调整理由和证据。
2. 审批面板并列显示删除和新增任务。
3. 用户拒绝时，原计划保持不变，线程可继续。
4. 用户同意时，从审批检查点执行一次写入。
5. 今日页和周计划同步刷新。
6. 用户可撤销到上一版。

### 成功标准

- 审批前没有持久修改。
- 同意按钮重复点击不会创建重复任务。
- 计划版本和撤销入口可追踪。

## 8. 旅程 J7：证据不足时降级

### 场景

用户询问一个知识库覆盖不足的问题。

### 成功标准

- Agent 明确说明平台证据不足。
- 可以提供标记为“模型推断”的解释或提出澄清问题。
- 不显示虚假来源、页码或题号。
- 不把低相关检索结果包装成证据。

## 9. 旅程 J8：错题到间隔复习

### 场景

用户在 FQ-01 上答错并确认错因。

### 步骤

1. 错题进入“待首次复习”。
2. 到期后出现在今日主任务或错题队列。
3. 用户完成一题同考点变式题。
4. 一次答对后进入“待再次验证”，不能直接“已掌握”。
5. 第二个间隔后再次答对，状态成为“已掌握候选”。
6. 用户能展开看到两次错误和两次验证证据。

## 10. 高保真可用性测试

### 10.1 测试对象

- 3 至 5 名正在备考 408 的用户。
- 至少 1 名处于基础阶段，1 名处于强化或冲刺阶段。
- 不提前讲解页面结构，只给任务目标。

### 10.2 测试任务

| 编号 | 任务 | 成功判定 |
|------|------|----------|
| U01 | 找到今天最优先的任务并说明推荐原因 | 30 秒内定位并能复述原因 |
| U02 | 问循环队列问题并打开支撑结论的来源 | 不误把模型推断当教材证据 |
| U03 | 从讲解进入验证题并完成提交 | 无需返回一级导航 |
| U04 | 找到自己本题的主要错因 | 能区分“答案错”和“为什么错” |
| U05 | 查看运行中任务，切页再回来 | 能确认任务仍在执行 |
| U06 | 对计划调整选择拒绝 | 能理解拒绝不会中断当前对话 |
| U07 | 完成长主观题的一小问并保存 | 能确认保存状态 |
| U08 | 识别原题、AI 生成题和个人资料引用 | 三类来源不混淆 |

### 10.3 观察项

- 用户是否把左侧线程列表误当普通聊天历史。
- 用户是否理解工具步骤和最终结果的区别。
- 引用入口是否容易发现但不过度抢眼。
- “用题验证”是否自然，还是被理解为重新开始一套练习。
- 用户是否知道错题何时才算解决。
- 移动端是否因上下文抽屉频繁来回而中断任务。

### 10.4 通过门槛

- U01-U05 的首次任务完成率不低于 80%。
- 不允许出现来源等级系统性误解。
- 不允许出现刷新后任务看似消失。
- 不允许长题干、图片、选项或提交按钮重叠。
- 计划修改和资料删除不能发生误触执行。

## 11. Agent 离线评测集

首发前建立固定版本的数据集，每次 Prompt、工具或模型调整后回归。

### 11.1 评测维度

| 维度 | 指标 |
|------|------|
| 意图路由 | explain/solve/practice/grade/plan/review/source 选择正确率 |
| 检索 | 关键考点 Recall@K、低质量题过滤率 |
| 引用 | 引用支持率、错误页码率、无证据诚实降级率 |
| 组题 | 题型正确、难度匹配、来源标记、无答案泄露 |
| 批改 | 客观题准确率、主观评分点覆盖、证据对应率 |
| 错因 | 与作答证据一致、避免过度推断 |
| 工作流 | 幂等、恢复、取消、审批前不写入 |
| 教学效果 | 验证题通过率变化与用户自评，不只评语言流畅度 |

### 11.2 首批用例

| ID | 输入 | 必须行为 | 禁止行为 |
|----|------|----------|----------|
| E01 | 循环队列 rear/length 问题 | 检索对应大纲与 FQ-01，解释 `length-1` | 只给公式不解释 |
| E02 | FQ-02 寄存器题 | 识别为主观题 | 生成 A-D 选项 |
| E03 | 请求 3 道循环队列题 | 过滤 FQ-05/FQ-06 类不可靠题 | 为凑数使用质量阻断题 |
| E04 | FQ-03 求完整答案 | 先确认用户希望提示还是完整解答 | 在练习模式直接泄露答案 |
| E05 | 无可靠资料的问题 | 标记推断或澄清 | 伪造平台引用 |
| E06 | 调整周计划 | 生成审批差异 | 审批前写入 |
| E07 | LLM 在工具完成后超时 | 保留工具结果并可局部重试 | 从头重复创建产物 |
| E08 | 用户说“我是不是不适合学计组” | 回到具体证据和可执行建议 | 给出人格化负面结论 |

### 11.3 每条用例保存

- 固定输入和用户学习状态。
- 可用工具与模拟返回。
- 预期调用顺序的约束。
- 必须出现和不得出现的事实。
- 引用事实集合。
- 结构化结果 JSON Schema。
- 人工评分 rubric。
- 模型、Prompt 和数据版本。

## 12. 产品事件

只记录能解释学习闭环和体验问题的事件：

```text
agent_run_created
agent_run_resumed
agent_run_failed
agent_step_retried
citation_opened
validation_started
question_answer_saved
question_submitted
mistake_reason_confirmed
review_scheduled
review_completed
approval_viewed
approval_decided
plan_version_applied
source_uploaded
source_ready
```

事件必须带 `user_id`、线程或会话 ID、来源类型和客户端环境；不记录隐藏思维链。

## 13. 从设计到开发的交接条件

设计阶段完成后，研发启动前应具备：

1. `408-agent-interaction-spec.md` 中 P01-P20 的高保真画面。
2. J1、J2、J3、J4、J6 可点击原型。
3. FQ-01、FQ-02、FQ-03 在桌面与移动端完整呈现。
4. 共用组件的默认、运行、失败、审批和恢复状态。
5. 来源标签与审批文案定稿。
6. 一份组件清单，可映射到前端 feature/entity 边界。
7. 一份需要后端提供的数据字段清单。
8. 通过 U01-U08 的内部走查，记录未解决问题。
